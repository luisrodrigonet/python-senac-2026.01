# Aula 10 — Organização e Manutenção de Templates com `Django Partials`

Django oferece três mecanismos complementares para evitar repetição de HTML: **herança de templates**, **`{% include %}`** e, a partir do Django 6.0, **Template Partials nativos**. No Django 6.1, os partials já fazem parte da linguagem de templates: **não é necessário instalar `django-template-partials` nem usar `{% load partials %}`**. 

## 1. Objetivos da aula 🎯

Ao final desta aula, você será capaz de:

- Criar um `template` base reutilizável com `{% extends %}` e `{% block %}`.
- Separar componentes como navbar, footer e cards com `{% include %}`.
- Definir fragmentos reutilizáveis dentro do mesmo arquivo com `{% partialdef %}`.
- Renderizar partials no template com `{% partial %}`.
- Renderizar apenas um fragmento a partir de uma view usando `template.html#nome_do_partial`.
- Escolher corretamente entre `block`, `include` e `partial`.

## 🧠 O problema: HTML repetido

Em um site real, páginas diferentes costumam compartilhar o mesmo `<head>`, menu, rodapé, CSS e JavaScript. Copiar esse código em cada arquivo gera manutenção duplicada: uma alteração simples, como trocar a versão do Bootstrap, exigiria editar todos os templates.

```html
<!-- produto.html -->
<!DOCTYPE html>
<html lang="pt-br">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Produtos</title>
    <link rel="stylesheet" href="styles.css">
</head>
<body>
    <h1>Produtos</h1>
</body>
</html>
```

```html
<!-- contato.html -->
<!DOCTYPE html>
<html lang="pt-br">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Contato</title>
    <link rel="stylesheet" href="styles.css">
</head>
<body>
    <h1>Contato</h1>
</body>
</html>
```

⚠️ Esse padrão viola o princípio **DRY** — *Don’t Repeat Yourself*, ou “não se repita”. Em projetos com dezenas de páginas, a repetição aumenta o risco de inconsistência visual e de erros.

## 🗂️ Analogia com CSS

| Abordagem | Exemplo | Vantagem | Problema |
|---|---|---|---|
| CSS inline | `<p style="color: blue;">` | Rápido para testes | Repetição e manutenção difícil |
| CSS interno | `<style>` dentro do HTML | Centraliza estilos da página | Não é reaproveitado entre páginas |
| CSS externo | `<link rel="stylesheet" href="styles.css">` | Reuso, cache e manutenção central | Exige organização de arquivos |

A melhor prática é usar **CSS externo**:

```html
<!-- Arquivo: static/css/styles.css -->
.texto-destaque {
    color: blue;
    font-size: 16px;
}
```

```html
<link rel="stylesheet" href="{% static 'css/styles.css' %}">
<p class="texto-destaque">Texto com estilo</p>
```

O Django aplica a mesma ideia ao HTML: em vez de repetir estrutura, criamos **um ponto único de manutenção**.

## 🏗️ Estrutura recomendada

```text
meu_projeto/
│
├── templates/
│   ├── base.html
│   └── partials/
│       ├── _navbar.html
│       ├── _footer.html
│       └── _card_produto.html
│
├── produtos/
│   ├── templates/
│   │   └── produtos/
│   │       ├── lista.html
│   │       └── detalhe.html
│   ├── views.py
│   ├── models.py
│   └── urls.py
│
└── static/
    ├── css/
    │   └── styles.css
    └── images/
        └── logo.png
```

📌 **Convenção útil:** use `_` no início do nome de arquivos que são apenas fragmentos, como `_navbar.html` e `_footer.html`. Isso deixa claro que eles não devem ser renderizados como páginas completas.

## 🧱 Herança de templates

A herança permite criar um template “pai” com a estrutura comum e templates “filhos” que preenchem apenas as partes variáveis.

### Template base

```html
<!-- templates/base.html -->
{% load static %}
<!DOCTYPE html>
<html lang="pt-br">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    
    <!-- Cada página pode definir sua própria descrição para SEO -->
    <meta name="description" content="{% block meta_description %}Aula de Django - Luis.Rodrigo.Net{% endblock %}">
    
    <!-- Titulo da página -->
    <title>{% block title %}Aula de Django - Luis.Rodrigo.Net{% endblock %}</title>

    
    <!-- Bootstrap 5.3.3 -->
    <link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css" rel="stylesheet">

    <!-- Font Awesome -->
    <!-- <link href="https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.7.2/css/all.min.css" rel="stylesheet"> -->
    <link href="https://cdnjs.cloudflare.com/ajax/libs/font-awesome/7.3.1/css/all.min.css" 
        integrity="sha512-QeR2VH+lsBE5LSAe1Q5EnTBbe7XTBubt8dG93Y7gidSgdMCr8nVqKcfKAMyN96SV8KDbZVTDXChatu5G2KQGzg==" 
        crossorigin="anonymous" referrerpolicy="no-referrer" rel="stylesheet" >
    
    <link rel="stylesheet" href="{% static 'css/style.css' %}">

    <!-- CSS do projeto -->
    <link rel="stylesheet" href="{% static 'css/styles.css' %}">    

    <!-- Espaço para CSS específico de uma página -->
    {% block extra_css %}{% endblock %}

</head>
<body>

    <header>
        {% include 'partials/_navbar.html' %}
    </header>

    <main class="container my-4">
        {% block content %}
            <p>Conteúdo padrão, caso a página filha não defina este bloco.</p>
        {% endblock %}
    </main>

    <footer class="bg-dark text-white mt-5">
        {% include 'partials/_footer.html' %}
    </footer>

    <script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/js/bootstrap.bundle.min.js"></script>

    {% block extra_js %}{% endblock %}
</body>
</html>
```

### Parâmetros e tags explicados

| Tag / recurso | Função | Detalhes importantes |
|---|---|---|
| `{% load static %}` | Habilita a tag `{% static %}` no template | Deve aparecer antes do primeiro uso de `{% static %}` |
| `{% static 'css/styles.css' %}` | Gera a URL correta do arquivo estático | O caminho é relativo a `STATIC_URL` e aos diretórios configurados |
| `{% block nome %}` | Define uma área substituível | Pode conter conteúdo padrão |
| `{% endblock %}` | Fecha o bloco | O nome é opcional: `{% endblock title %}` melhora a legibilidade |
| `{% include %}` | Renderiza outro template e insere o HTML resultante | O template incluído recebe o contexto atual, salvo se você usar `only` |
| `{% url 'nome' %}` | Gera URL a partir do `name` definido em `urls.py` | Evita links fixos como `/produtos/` |
| `{% csrf_token %}` | Insere o token de proteção contra CSRF | Obrigatório em formulários `POST` |

O `{% block %}` define regiões que templates filhos podem sobrescrever; o `{% include %}` carrega e renderiza um subtemplate com o contexto atual. 

### Template filho

```html
<!-- produtos/templates/produtos/lista.html -->
{% extends 'base.html' %}

{% block title %}Lista de Produtos — Minha Loja{% endblock %}

{% block meta_description %}
Confira nossa seleção completa de produtos.
{% endblock %}

{% block extra_css %}
<style>
    .produto-card {
        transition: transform 0.2s ease;
    }

    .produto-card:hover {
        transform: scale(1.03);
    }
</style>
{% endblock %}

{% block content %}
    <h1 class="mb-4">Nossos Produtos</h1>

    <div class="row g-4">
        {% for produto in produtos %}
            <div class="col-md-4">
                {% include 'partials/_card_produto.html' %}
            </div>
        {% empty %}
            <div class="col-12">
                <div class="alert alert-info">
                    Nenhum produto disponível no momento.
                </div>
            </div>
        {% endfor %}
    </div>
{% endblock %}
```

### Como funciona a herança

1. `{% extends 'base.html' %}` informa que o template herda a estrutura do `base.html`.
2. `{% block title %}` substitui apenas o conteúdo daquele bloco.
3. Blocos não sobrescritos permanecem com o conteúdo definido no template pai.
4. `{% for %}` percorre a lista `produtos`; `{% empty %}` é executado quando a lista está vazia.

O `{% extends %}` aceita uma string entre aspas, uma variável de contexto ou caminhos relativos como `./base.html` e `../base.html`. 

## 🧩 Componentes com `{% include %}`

Use `{% include %}` quando um fragmento será reaproveitado em **vários templates diferentes**, como navbar, footer, modal ou card.

## 📦 `include` com variáveis

Por padrão, o template incluído recebe o contexto do template que o inclui. Você também pode passar variáveis extras com `with`.

```html
<!-- templates/partials/_card_produto.html -->
<div class="card h-100 shadow-sm">
    {% if produto.imagem %}
        <img
            src="{{ produto.imagem.url }}"
            class="card-img-top"
            alt="{{ produto.nome }}"
            style="height: 200px; object-fit: cover;"
        >
    {% endif %}

    <div class="card-body d-flex flex-column">
        <h5 class="card-title">{{ produto.nome }}</h5>
        <p class="card-text flex-grow-1">
            {{ produto.descricao|truncatewords:15 }}
        </p>

        <p class="text-primary fw-bold mb-3">
            R$ {{ produto.preco|floatformat:2 }}
        </p>

        {% if mostrar_botao %}
            <a
                href="{% url 'produtos:detalhe' produto.pk %}"
                class="btn btn-primary mt-auto"
            >
                {{ texto_botao|default:'Ver detalhes' }}
            </a>
        {% endif %}
    </div>
</div>
```

```html
<!-- Uso com variáveis extras -->
{% include 'partials/_card_produto.html' with mostrar_botao=True texto_botao='Comprar agora' %}
```

### Opções do `{% include %}`

| Opção | Exemplo | Explicação |
|---|---|---|
| Template fixo | `{% include 'partials/_navbar.html' %}` | Inclui sempre o mesmo arquivo |
| Template dinâmico | `{% include nome_template %}` | O nome do arquivo vem de uma variável |
| `with` | `{% include 'x.html' with titulo='Oferta' %}` | Adiciona variáveis ao contexto do include |
| `only` | `{% include 'x.html' with titulo='Oferta' only %}` | Envia apenas as variáveis declaradas; oculta o restante do contexto |

O `with` permite passar pares `chave=valor`, e o `only` restringe o contexto exclusivamente às variáveis informadas. 

## ⚡ Template Partials no Django 6.1

Os **Template Partials** foram introduzidos no Django 6.0 e permitem definir fragmentos nomeados dentro do próprio template. Eles são úteis quando um bloco HTML se repete várias vezes **no mesmo arquivo** ou quando uma view precisa retornar somente aquele fragmento. 

### Sintaxe básica

```html
{% partialdef nome_do_partial %}
    <!-- HTML reutilizável -->
{% endpartialdef %}

{% partial nome_do_partial %}
```

| Tag | Função |
|---|---|
| `{% partialdef nome %}` | Define um fragmento reutilizável |
| `{% endpartialdef %}` | Fecha a definição do partial |
| `{% partial nome %}` | Renderiza o partial naquele ponto |
| `inline` | Renderiza o partial imediatamente e continua permitindo reuso posterior |

O nome do partial é obrigatório e deve ser um identificador válido de template. 

### Exemplo: card de produto

```html
<!-- produtos/templates/produtos/lista.html -->
{% extends 'base.html' %}
{% load static %}

{% block title %}Lista de Produtos — Minha Loja{% endblock %}

{% block content %}
    <h1 class="mb-4">Catálogo de Produtos</h1>

    {# Define o partial uma única vez #}
    {% partialdef card-produto %}
        <div class="card h-100 shadow-sm">
            {% if produto.imagem %}
                <img
                    src="{{ produto.imagem.url }}"
                    class="card-img-top"
                    alt="{{ produto.nome }}"
                    style="height: 200px; object-fit: cover;"
                >
            {% endif %}

            <div class="card-body d-flex flex-column">
                <h5 class="card-title">{{ produto.nome }}</h5>

                <p class="card-text flex-grow-1">
                    {{ produto.descricao|truncatewords:15 }}
                </p>

                <p class="text-primary fw-bold mb-3">
                    R$ {{ produto.preco|floatformat:2 }}
                </p>

                <a
                    href="{% url 'produtos:detalhe' produto.pk %}"
                    class="btn btn-primary mt-auto"
                >
                    Ver detalhes
                </a>
            </div>
        </div>
    {% endpartialdef card-produto %}

    <div class="row g-4">
        {% for produto in produtos %}
            <div class="col-md-4">
                {# Renderiza o partial para cada produto #}
                {% partial card-produto %}
            </div>
        {% empty %}
            <div class="col-12">
                <div class="alert alert-warning">
                    Nenhum produto encontrado.
                </div>
            </div>
        {% endfor %}
    </div>
{% endblock %}
```

### `inline`: definir e renderizar ao mesmo tempo

```html
{% partialdef botao-salvar inline %}
    <button type="submit" class="btn btn-success">
        Salvar
    </button>
{% endpartialdef %}
```

Com `inline`, o conteúdo é renderizado imediatamente no local da definição. Mesmo assim, o partial continua armazenado e pode ser chamado depois com `{% partial botao-salvar %}`. 

## 🔁 Partial versus include

| Critério | `{% block %}` | `{% include %}` | `{% partialdef %}` + `{% partial %}` |
|---|---|---|---|
| Objetivo | Permitir que páginas filhas substituam áreas do layout | Reutilizar um arquivo HTML em vários templates | Reutilizar um fragmento dentro do mesmo template |
| Escopo | Herança de templates | Entre arquivos diferentes | Dentro de um arquivo |
| Recebimento de contexto | Herda o contexto da página | Herda o contexto atual; aceita `with` e `only` | Usa o contexto disponível no ponto de renderização |
| Exemplo ideal | `title`, `content`, `extra_js` | Navbar, footer, modal, card compartilhado | Card repetido em uma listagem |
| Renderização via view | Não é o caso de uso principal | Possível, mas retorna o arquivo inteiro | Ideal: `lista.html#card-produto` |

**Regra prática:** use `block` para áreas do layout que mudam por página; use `include` para componentes compartilhados entre páginas; use partials para fragmentos repetidos no mesmo template ou retornados isoladamente por AJAX/HTMX.

## 🧪 Renderizando apenas um partial

Essa é uma das maiores vantagens dos partials nativos. Você pode solicitar somente um fragmento usando a sintaxe:

```text
caminho/do/template.html#nome_do_partial
```

```python
# produtos/views.py
from django.shortcuts import get_object_or_404, render
from .models import Produto


def detalhe_partial(request, pk):
    """
    Retorna apenas o partial 'card-produto' do template lista.html.
    Útil para HTMX, AJAX ou atualizações parciais de página.
    """
    produto = get_object_or_404(Produto, pk=pk)

    return render(
        request,
        'produtos/lista.html#card-produto',
        {'produto': produto},
    )
```

A sintaxe `template.html#partial` funciona com `get_template()`, `render()`, `{% include %}` e outras ferramentas de carregamento de templates. 

### Exemplo com HTMX

```html
<!-- Botão que atualiza somente o card, sem recarregar a página -->
<button
    hx-get="{% url 'produtos:card' produto.pk %}"
    hx-target="closest .card"
    hx-swap="outerHTML"
    class="btn btn-outline-secondary btn-sm"
>
    Atualizar
</button>
```

Nesse caso, o servidor devolve apenas o HTML do partial, e o HTMX substitui somente o card na página.

## 🔐 Boas práticas

- ✅ Coloque `{% extends %}` na **primeira linha** do template filho.
- ✅ Use nomes descritivos: `card-produto`, `formulario-contato`, `linha-pedido`.
- ✅ Prefira `include` para componentes usados em várias páginas.
- ✅ Prefira partials para repetições dentro do mesmo template ou respostas parciais.
- ✅ Nunca confie apenas no JavaScript para validação: valide os dados também na view.
- ✅ Use `{% csrf_token %}` em todo formulário `POST`.
- ✅ Evite `|safe` sem necessidade: ele desativa o escape automático e pode abrir espaço para XSS.
- ✅ Mantenha partials pequenos e com uma responsabilidade clara.

## 🧾 Resumo dos comandos

```html
{# Herança #}
{% extends 'base.html' %}
{% block content %} ... {% endblock content %}

{# Componente em arquivo separado #}
{% include 'partials/_navbar.html' %}
{% include 'partials/_card_produto.html' with mostrar_botao=True only %}

{# Partial nativo do Django 6.1 #}
{% partialdef card-produto %}
    <!-- HTML -->
{% endpartialdef card-produto %}

{% partial card-produto %}

{# Partial inline #}
{% partialdef botao-salvar inline %}
    <button class="btn btn-success">Salvar</button>
{% endpartialdef botao-salvar %}

{# Renderização isolada em view #}
{# render(request, 'produtos/lista.html#card-produto', contexto) #}
```

Os partials nativos do Django tornam os templates mais modulares sem depender de pacotes externos: `{% partialdef %}` define o fragmento, `{% partial %}` o renderiza e a sintaxe `template#partial` permite retornar somente aquele pedaço de HTML.
