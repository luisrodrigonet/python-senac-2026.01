s# Aula 10 — Exemplo de uso de **partials** no Django 6.1 🍽️

Continuando a aplicação `receitas` da Aula 9. O foco é usar **template partials**, recurso introduzido no Django 6.0, para evitar repetição de HTML e criar componentes reutilizáveis. 

## 🎯 Objetivo da aula

Ao final desta aula, você será capaz de:

- Entender a diferença entre `include`, `partialdef` e `partial`.
- Criar componentes reutilizáveis para cards de receitas, formulários, mensagens e paginação.
- Renderizar apenas um fragmento de template, útil para atualizações parciais de página.
- Organizar melhor os templates da aplicação `receitas`.

No Django, um **template partial** é um fragmento nomeado dentro de um arquivo de template. Ele pode ser renderizado várias vezes no mesmo arquivo ou acessado diretamente pela sintaxe `template.html#nome_do_partial`. 

## 🧩 Partials x include

| Recurso | Quando usar | Exemplo |
|---|---|---|
| `{% include %}` | Reutilizar um arquivo de template separado | `{% include "receitas/partials/card_receita.html" %}` |
| `{% partialdef %}` | Definir um fragmento nomeado dentro do próprio template | `{% partialdef card %}...{% endpartialdef %}` |
| `{% partial %}` | Renderizar um fragmento definido com `partialdef` | `{% partial card %}` |
| `template.html#partial` | Acessar um partial de outro template ou via view | `{% include "receitas/lista.html#card" %}` |

O `include` carrega e renderiza outro template com o contexto atual; já os partials permitem definir e reutilizar fragmentos nomeados sem criar um arquivo novo para cada componente pequeno.

## 2. Modelo base 🧱

Suponha que a Aula 9 criou estes modelos:

```python
# receitas/models.py
from django.db import models
from django.urls import reverse


class Categoria(models.Model):
    """Categoria usada para agrupar receitas."""

    nome = models.CharField(
        max_length=100,
        unique=True,            # <-- Atualziar
        verbose_name="Nome",    # <-- Atualziar
    )

    class Meta:
        verbose_name = "Categoria"
        verbose_name_plural = "Categorias"
        ordering = ["nome"]

    def __str__(self):
        return self.nome


class Receita(models.Model):
    """Representa uma receita culinária."""

    titulo = models.CharField(
        max_length=200,
        verbose_name="Título",      # <-- Atualziar
    )

    descricao = models.TextField(   # <-- Atualziar
        verbose_name="Descrição",   # <-- Atualziar
    )                               # <-- Atualziar

    ingredientes = models.TextField(
        help_text="Informe um ingrediente por linha."
    )

    modo_preparo = models.TextField(
        verbose_name="Modo de preparo", # <-- Atualziar
    )

    tempo_preparo_minutos = models.PositiveIntegerField(
        verbose_name="Tempo de preparo (minutos)",  # <-- Atualziar
    )

    categoria = models.ForeignKey(
        Categoria,
        on_delete=models.PROTECT,
        related_name="receitas",
        verbose_name="Categoria",
        blank=True,                     # <-- Atualziar
    )

    # Relação 1:N: cada receita pertence a um autor.
    autor = models.ForeignKey(
        User,
        on_delete=models.CASCADE,
        related_name="receitas",
    )

    data_publicacao = models.DateTimeField(
        auto_now_add=True,
    )

    atualizada_em = models.DateTimeField(
        auto_now=True,
        verbose_name="Atualizada em",
    )

    class Meta:
        verbose_name = "Receita"
        verbose_name_plural = "Receitas"
        ordering = ["-data_publicacao"]

    def __str__(self):
        return self.titulo

    def get_absolute_url(self):
        """Retorna a URL de detalhe da receita."""
        return reverse("receitas:detalhe_receita", args=[self.pk])
```

### 2.1. Explicação dos principais parâmetros

- `max_length`: limite máximo de caracteres; obrigatório em `CharField`.
- `unique=True`: impede dois registros com o mesmo valor.
- `TextField`: campo para textos longos, sem limite fixo no banco.
- `PositiveIntegerField`: aceita apenas números inteiros maiores ou iguais a zero.
- `default=1`: valor inicial usado quando o campo não é informado.
- `on_delete=models.PROTECT`: impede excluir uma categoria que ainda possui receitas.
- `related_name="receitas"`: permite acessar as receitas de uma categoria com `categoria.receitas.all()`.
- `auto_now_add=True`: grava a data/hora apenas na criação.
- `auto_now=True`: atualiza a data/hora a cada salvamento.
- `get_absolute_url()`: retorna a URL canônica do objeto; é útil em `CreateView`, `UpdateView` e templates.

```python
from django import forms

from .models import Receita

class ReceitaForm(forms.ModelForm):
    """Formulário para criar e editar receitas."""

    class Meta:
        model = Receita
        fields = [
            "titulo",
            "ingredientes",
            "modo_preparo",
            "tempo_preparo",
            "categorias",
        ]
        widgets = {
            "titulo": forms.TextInput(
                attrs={
                    "class": "form-control",
                    "placeholder": "Ex.: Bolo de cenoura",
                }
            ),
            "ingredientes": forms.Textarea(
                attrs={
                    "class": "form-control",
                    "rows": 5,
                    "placeholder": "Informe um ingrediente por linha.",
                }
            ),
            "modo_preparo": forms.Textarea(
                attrs={
                    "class": "form-control",
                    "rows": 8,
                }
            ),
            "tempo_preparo": forms.NumberInput(
                attrs={
                    "class": "form-control",
                    "min": 0,
                }
            ),
            "categorias": forms.SelectMultiple(
                attrs={
                    "class": "form-select",
                }
            ),
        }
        labels = {
            "titulo": "Título",
            "ingredientes": "Ingredientes",
            "modo_preparo": "Modo de preparo",
            "tempo_preparo": "Tempo de preparo (minutos)",
            "categorias": "Categorias",
        }
```

### 4.1. Explicação do `ModelForm`

- `model = Receita`: indica qual modelo será usado.
- `fields`: define explicitamente os campos exibidos; é mais seguro do que usar `fields = "__all__"`.
- `widgets`: personaliza o HTML gerado para cada campo.
- `attrs`: adiciona atributos HTML, como classes CSS, `placeholder`, `rows` e `min`.
- `labels`: substitui os rótulos padrão gerados pelo Django.


## 5. Views com partial 🧠 

```python
# receitas/views.py
from django.shortcuts import get_object_or_404, render
from django.contrib import messages
from django.contrib.messages.views import SuccessMessageMixin
from django.urls import reverse_lazy
from django.views.generic import (
    CreateView,
    DeleteView,
    DetailView,
    ListView,
    UpdateView,
)

from .forms import ReceitaForm
from .models import Receita


class ReceitaListView(ListView):
    """Exibe a lista paginada de receitas."""

    model = Receita
    template_name = "receitas/lista_receitas.html"
    context_object_name = "receitas"
    paginate_by = 6


class ReceitaDetailView(DetailView):
    """Exibe os detalhes de uma receita."""

    model = Receita
    template_name = "receitas/detalhe_receita.html"
    context_object_name = "receita"


class ReceitaCreateView(SuccessMessageMixin, CreateView):
    """Cadastra uma nova receita."""

    model = Receita
    form_class = ReceitaForm
    template_name = "receitas/formulario_receita.html"
    success_message = "Receita cadastrada com sucesso!"


class ReceitaUpdateView(SuccessMessageMixin, UpdateView):
    """Edita uma receita existente."""

    model = Receita
    form_class = ReceitaForm
    template_name = "receitas/formulario_receita.html"
    success_message = "Receita atualizada com sucesso!"


class ReceitaDeleteView(DeleteView):
    """Confirma e exclui uma receita."""

    model = Receita
    template_name = "receitas/confirmar_exclusao.html"
    success_url = reverse_lazy("receitas:lista_receitas")
    success_message = "Receita excluída com sucesso!"

    def form_valid(self, form):
        """Adiciona mensagem antes de concluir a exclusão."""
        messages.success(self.request, self.success_message)
        return super().form_valid(form)


def receita_card_partial(request, pk):
    """
    Renderiza apenas o partial do card de uma receita.

    Útil para requisições AJAX, HTMX ou atualização de um card isolado.
    """
    receita = get_object_or_404(Receita, pk=pk)

    return render(
        request,
        "receitas/lista_receitas.html#card_receita",
        {"receita": receita},
    )
```

### 5.1. Explicação das classes genéricas

- `ListView`: lista objetos do modelo.
- `DetailView`: exibe um objeto específico.
- `CreateView`: exibe e processa um formulário de criação.
- `UpdateView`: exibe e processa um formulário de edição.
- `DeleteView`: exibe confirmação e exclui o objeto.
- `SuccessMessageMixin`: adiciona automaticamente uma mensagem de sucesso após criar ou editar.
- `paginate_by`: define quantos itens aparecem por página.
- `context_object_name`: define o nome da variável disponível no template.
- `reverse_lazy()`: resolve a URL somente quando necessário, evitando problemas durante o carregamento inicial das classes.

A função `receita_card_partial` usa a sintaxe `lista_receitas.html#card_receita`, que instrui o Django a renderizar **somente o partial** chamado `card_receita`, e não a página completa.

```django
                class="btn btn-light"
                href="{% url 'receitas:criar_receita' %}"
            >
                ➕ Nova receita
            </a>
        </div>
    </nav>

    <main class="container pb-5">
        {% include "receitas/partials/mensagens.html" %}

        {% block conteudo %}
        {% endblock %}
    </main>

</body>
</html>
```

### 6.1. Explicação das tags

- `{% block titulo %}`: cria uma área substituível nas páginas filhas.
- `{% url 'receitas:lista_receitas' %}`: gera a URL pelo nome da rota.
- `{% include "..." %}`: insere e renderiza outro template.
- `{% block conteudo %}`: área onde cada página insere seu conteúdo específico.

O `include` renderiza o subtemplate de forma independente; ele não compartilha estado com o template pai, embora receba o contexto atual por padrão.

### 7.1. Explicação

- `alert-dismissible`: habilita o botão de fechar do Bootstrap.
- `data-bs-dismiss="alert"`: atributo usado pelo Bootstrap para fechar o alerta.

## 8. Partial de card de receita 🃏 

Este é o exemplo central da aula. O partial é definido dentro do próprio template de listagem e pode ser renderizado várias vezes.

```django
{# receitas/templates/receitas/lista_receitas.html #}
{% extends "receitas/_base_receitas.html" %}

{% block titulo %}Lista de receitas{% endblock %}

{% block conteudo %}
    <div class="d-flex justify-content-between align-items-center mb-4">
        <h1 class="h3 mb-0">📚 Receitas cadastradas</h1>

        <a
            class="btn btn-primary"
            href="{% url 'receitas:criar_receita' %}"
        >
            ➕ Nova receita
        </a>
    </div>

    {% if receitas %}
        <div class="row g-4">
            {% for receita in receitas %}
                {% partial card_receita %}
            {% endfor %}
        </div>
    {% else %}
        <div class="alert alert-info">
            Nenhuma receita cadastrada ainda. 🧑‍🍳
        </div>
    {% endif %}

    {% include "receitas/partials/_paginacao.html" %}
{% endblock %}


{% partialdef card_receita %}
    <div class="col-12 col-md-6 col-lg-4">
        <div class="card h-100 shadow-sm">
            <div class="card-body d-flex flex-column">
                <span class="badge bg-secondary align-self-start mb-2">
                    {{ receita.categoria.nome }}
                </span>

                <h2 class="h5 card-title">{{ receita.titulo }}</h2>

                <p class="card-text text-secondary flex-grow-1">
                    {{ receita.descricao|truncatewords:20 }}
                </p>

                <ul class="list-unstyled small mb-3">
                    <li>⏱️ {{ receita.tempo_preparo_minutos }} minutos</li>
                    <li>🍽️ {{ receita.porcoes }} porções</li>
                </ul>

                <div class="d-flex gap-2">
                    <a
                        class="btn btn-sm btn-outline-primary"
                        href="{% url 'receitas:detalhe_receita' receita.pk %}"
                    >
                        Ver detalhes
                    </a>

                    <a
                        class="btn btn-sm btn-outline-secondary"
                        href="{% url 'receitas:editar_receita' receita.pk %}"
                    >
                        Editar
                    </a>
                </div>
            </div>
        </div>
    </div>
{% endpartialdef card_receita %}
```

### 8.1. Explicação dos partials

```django
{% partialdef card_receita %}
    <!-- Conteúdo reutilizável -->
{% endpartialdef card_receita %}
```

- `{% partialdef card_receita %}`: **define** um fragmento nomeado.
- `card_receita`: nome do partial; deve ser um identificador válido.
- `{% endpartialdef card_receita %}`: encerra o partial; repetir o nome é opcional, mas melhora a legibilidade.
- O conteúdo entre as tags não é renderizado automaticamente na definição.
- `{% partial card_receita %}`: **renderiza** o partial naquele ponto do template.
- O partial recebe o contexto atual; dentro do `for`, a variável `receita` é atualizada a cada repetição. 

### 8.2. Filtros usados

- `{{ receita.descricao|truncatewords:20 }}`: exibe apenas as primeiras 20 palavras da descrição.
- `{{ receita.categoria.nome }}`: acessa o campo `nome` do objeto relacionado `categoria`.
- `{{ receita.pk }}`: chave primária da receita.

## 9. Partial de paginação 📄

```django
{# receitas/templates/receitas/partials/_paginacao.html #}
{% if page_obj.has_other_pages %}
    <nav aria-label="Paginação de receitas" class="mt-4">
        <ul class="pagination justify-content-center">

            {% if page_obj.has_previous %}
                <li class="page-item">
                    <a
                        class="page-link"
                        href="?page={{ page_obj.previous_page_number }}"
                    >
                        &laquo; Anterior
                    </a>
                </li>
            {% else %}
                <li class="page-item disabled">
                    <span class="page-link">&laquo; Anterior</span>
                </li>
            {% endif %}

            {% for num in page_obj.paginator.page_range %}
                {% if page_obj.number == num %}
                    <li class="page-item active">
                        <span class="page-link">{{ num }}</span>
                    </li>
                {% else %}
                    <li class="page-item">
                        <a class="page-link" href="?page={{ num }}">
                            {{ num }}
                        </a>
                    </li>
                {% endif %}
            {% endfor %}

            {% if page_obj.has_next %}
                <li class="page-item">
                    <a
                        class="page-link"
                        href="?page={{ page_obj.next_page_number }}"
                    >
                        Próxima &raquo;
                    </a>
                </li>
            {% else %}
                <li class="page-item disabled">
                    <span class="page-link">Próxima &raquo;</span>
                </li>
            {% endif %}

        </ul>
    </nav>
{% endif %}
```

### 9.1. Explicação das variáveis de paginação

- `page_obj`: objeto da página atual, criado automaticamente pelo `ListView` quando `paginate_by` está configurado.
- `page_obj.has_other_pages`: indica se existe mais de uma página.
- `page_obj.has_previous`: verifica se há página anterior.
- `page_obj.previous_page_number`: número da página anterior.
- `page_obj.has_next`: verifica se há próxima página.
- `page_obj.next_page_number`: número da próxima página.
- `page_obj.paginator.page_range`: intervalo de todas as páginas disponíveis.
- `page_obj.number`: número da página atual.
- `?page={{ num }}`: envia o número da página pela query string.

##  10. Partial de formulário 🧾

```django
{# receitas/templates/receitas/partials/_formulario_receita.html #}
{% if form.non_field_errors %}
    <div class="alert alert-danger">
        {% for erro in form.non_field_errors %}
            <p class="mb-0">{{ erro }}</p>
        {% endfor %}
    </div>
{% endif %}

<form method="post" novalidate>
    {% csrf_token %}

    {% for field in form %}
        <div class="mb-3">
            <label for="{{ field.id_for_label }}" class="form-label">
                {{ field.label }}
            </label>

            {{ field }}

            {% if field.help_text %}
                <div class="form-text">{{ field.help_text }}</div>
            {% endif %}

            {% for erro in field.errors %}
                <div class="text-danger small mt-1">
                    {{ erro }}
                </div>
            {% endfor %}
        </div>
    {% endfor %}

    <div class="d-flex gap-2">
        <button type="submit" class="btn btn-primary">
            💾 Salvar
        </button>

        <a
            class="btn btn-outline-secondary"
            href="{% url 'receitas:lista_receitas' %}"
        >
            Cancelar
        </a>
    </div>
</form>
```

### 10.1. Explicação dos itens do formulário

- `form.non_field_errors`: erros que não pertencem a um campo específico.
- `method="post"`: envia os dados no corpo da requisição; obrigatório para alterações no banco.
- `{% csrf_token %}`: protege contra ataques CSRF.
- `novalidate`: desativa a validação nativa do navegador, permitindo ver também as validações do Django.
- `field.id_for_label`: gera o `id` correto para associar o `label` ao campo.
- `field.help_text`: texto de ajuda definido no modelo ou formulário.
- `field.errors`: erros de validação daquele campo.

```django
                    🗑️ Excluir
                </a>

                <a
                    class="btn btn-outline-secondary"
                    href="{% url 'receitas:lista_receitas' %}"
                >
                    ⬅️ Voltar
                </a>
            </div>
        </div>
    </div>
{% endblock %}
```

O filtro `linebreaks` converte quebras de linha do texto em tags HTML de parágrafo e quebra de linha, preservando a formatação digitada pelo usuário.

## 13 Reaproveitando um partial em outro template ♻️

Você também pode usar o partial `card_receita` definido em `lista_receitas.html` em outra página:

```django
{% include "receitas/lista_receitas.html#card_receita" %}
```

Ou renderizá-lo diretamente em uma view:

```python
from django.shortcuts import render

from .models import Receita


def card_receita(request, pk):
    """Renderiza somente o card da receita solicitada."""
    receita = Receita.objects.get(pk=pk)

    return render(
        request,
        "receitas/lista_receitas.html#card_receita",
        {"receita": receita},
    )
```

A sintaxe `arquivo.html#nome_do_partial` é suportada por `render()`, `get_template()` e `{% include %}` no Django 6.1. 

## 14 Boas práticas ✅

- Use `include` para componentes maiores ou compartilhados entre vários templates.
- Use `partialdef` e `partial` para fragmentos pequenos, nomeados e reutilizados no mesmo template.
- Prefira `fields` explícitos em vez de `fields = "__all__"`.
- Sempre use `{% csrf_token %}` em formulários `POST`.
- Use `get_object_or_404()` quando o objeto deve existir obrigatoriamente.
- Dê nomes claros aos partials: `card_receita`, `formulario_receita`, `paginacao`.
- Evite colocar lógica complexa nos templates; ela deve ficar prioritariamente em models, forms e views.
