# 🍳 Aula 09 — Admin: Registrando os Modelos no Django 6.1

O Django Admin é uma interface administrativa pronta para uso que gera telas de **CRUD** — **Create, Read, Update e Delete** — a partir dos metadados dos seus modelos. Porém, um modelo só aparece no Admin depois de ser **registrado explicitamente** em `admin.py`. [docs.djangoproject](https://docs.djangoproject.com/en/6.1/ref/contrib/admin/)

Nesta aula, registraremos os modelos `Categoria` e `Receita` da aplicação `receitas`, primeiro de forma simples e depois com personalização por meio da classe `ModelAdmin`.

***

## ✅ Pré-requisitos

Antes de registrar os modelos, garanta que:

- A aplicação `receitas` está em `INSTALLED_APPS`;
- Os modelos `Categoria` e `Receita` já existem em `receitas/models.py`;
- As migrações foram criadas e aplicadas;
- O projeto possui um superusuário.

O Admin depende dos apps `django.contrib.admin`, `django.contrib.auth`, `django.contrib.contenttypes`, `django.contrib.messages` e `django.contrib.sessions`, que normalmente já vêm configurados no `settings.py` de um projeto Django. [docs.djangoproject](https://docs.djangoproject.com/en/1.8//ref/contrib/admin/)

***

## 🧱 Passo 0 — Aplicando migrações

Sempre que você criar ou alterar um modelo, execute:

```bash
# Cria arquivos de migração com base nas alterações dos modelos
python manage.py makemigrations

# Aplica as migrações no banco de dados
python manage.py migrate
```

### 🔍 Explicação

| Comando | O que faz |
|---|---|
| `makemigrations` | Lê os modelos e gera arquivos Python em `migrations/` descrevendo as alterações |
| `migrate` | Executa essas migrações e altera a estrutura real do banco de dados |

⚠️ **Atenção:** `makemigrations` **não altera o banco**. Ele apenas prepara as instruções. Quem altera o banco é o `migrate`.

## 🧩 Passo 1 — Importando os componentes

Abra o arquivo:

```text
receitas/admin.py
```

E adicione:

```python
# receitas/admin.py

# Importa o módulo de administração do Django.
# Ele fornece admin.site, o decorador @admin.register e a classe ModelAdmin.
from django.contrib import admin

# Importa os modelos que serão exibidos no painel administrativo.
# O ponto inicial indica importação relativa: estamos importando
# do arquivo models.py localizado na mesma aplicação.
from .models import Categoria, Receita
```

### 🔍 Explicação

- `from django.contrib import admin`: importa o sistema de Admin do Django.
- `from .models import Categoria, Receita`: importa os modelos criados na aplicação.
- O ponto (`.`) significa “nesta mesma pasta/aplicação”.

## 🚀 Passo 2 — Registro básico

A forma mais direta de expor um modelo no Admin é:

```python
# receitas/admin.py

# Registra o modelo Categoria com a configuração padrão do Django Admin.
admin.site.register(Categoria)

# Registra o modelo Receita com a configuração padrão do Django Admin.
admin.site.register(Receita)
```

### 🔍 Como funciona

A assinatura oficial é:

```python
admin.site.register(model_or_iterable, admin_class=None, **options)
```

| Parâmetro | Descrição |
|---|---|
| `model_or_iterable` | O modelo ou uma lista/tupla de modelos a registrar |
| `admin_class` | Classe opcional derivada de `ModelAdmin` com personalizações |
| `**options` | Opções de `ModelAdmin` passadas diretamente, como `list_display` |

O Django usa `ModelAdmin` como classe padrão quando nenhuma personalização é informada. Ele também gera erro `AlreadyRegistered` se o mesmo modelo for registrado duas vezes. [docs.djangoproject](https://docs.djangoproject.com/en/6.1/ref/contrib/admin/)

### 📌 Registro em lote

Você também pode registrar vários modelos de uma vez:

```python
# Registra Categoria e Receita usando a configuração padrão.
admin.site.register([Categoria, Receita])
```

Essa forma é útil para modelos simples, mas oferece pouco controle sobre listagem, filtros e formulários.

## 👤 Passo 3 — Criando o superusuário

Para acessar o Admin, crie um usuário administrador:

```bash
python manage.py createsuperuser
```

O terminal solicitará:

```text
Username:
Email address:
Password:
Password (again):
```

### 🔍 Explicação

- **Username:** nome de usuário para login.
- **Email:** opcional em muitos projetos, mas recomendado.
- **Password:** deve atender às validações padrão do Django; em ambiente de estudo, o Django pode permitir uma senha simples após confirmação.

Depois, inicie o servidor:

```bash
python manage.py runserver
```

Acesse:

```text
http://127.0.0.1:8000/admin/
```

Faça login com o superusuário criado. Você verá os modelos `Categoria` e `Receita` disponíveis para criação, edição, exclusão e listagem.

## 🎛️ Passo 4 — Personalizando com `ModelAdmin`

O registro básico funciona, mas a listagem padrão normalmente mostra apenas o retorno do método `__str__`. Para criar uma área administrativa realmente útil, use uma classe que herde de `admin.ModelAdmin`.

```python
# receitas/admin.py

from django.contrib import admin
from .models import Categoria, Receita


# Registro simples para Categoria.
# Como Categoria normalmente possui poucos registros,
# a configuração padrão já é adequada.
admin.site.register(Categoria)


# O decorador registra o modelo Receita utilizando a classe ReceitaAdmin.
# É a forma recomendada porque mantém modelo e configuração próximos.
@admin.register(Receita)
class ReceitaAdmin(admin.ModelAdmin):
    """
    Personaliza a interface administrativa do modelo Receita.
    """

    # Define as colunas exibidas na página de listagem.
    list_display = (
        "titulo",
        "autor",
        "tempo_preparo",
        "publicada",
        "data_publicacao",
    )

    # Cria filtros na lateral direita da listagem.
    list_filter = (
        "publicada",
        "autor",
        "categorias",
        "data_publicacao",
    )

    # Cria o campo de busca no topo da listagem.
    search_fields = (
        "titulo",
        "ingredientes",
        "modo_preparo",
    )

    # Permite editar o campo diretamente na listagem,
    # sem abrir a página de detalhe do objeto.
    list_editable = (
        "publicada",
    )

    # Substitui o select tradicional de ForeignKey por um campo
    # onde o administrador digita o ID do autor.
    # É útil quando existem muitos usuários cadastrados.
    raw_id_fields = (
        "autor",
    )
```

### 🔍 Explicação detalhada das opções

| Opção | Função | Observação importante |
|---|---|---|
| `list_display` | Define as colunas da tabela de listagem | Pode receber nomes de campos, propriedades ou métodos do `ModelAdmin` |
| `list_filter` | Cria filtros laterais | Funciona bem com `BooleanField`, `ForeignKey`, `ManyToManyField` e datas |
| `search_fields` | Habilita busca textual | O Django normalmente usa busca com `icontains` |
| `list_editable` | Permite edição inline na listagem | O campo precisa também estar em `list_display` |
| `raw_id_fields` | Exibe um campo de ID para relacionamentos | Indicado para tabelas com muitos registros |
| `@admin.register(Receita)` | Registra o modelo com a classe personalizada | Alternativa mais legível a `admin.site.register(Receita, ReceitaAdmin)` |

### ⚠️ Regra importante do `list_editable`

Este código está **correto**:

```python
list_display = ("titulo", "autor", "publicada")
list_editable = ("publicada",)
```

Este código está **errado**:

```python
list_display = ("titulo", "autor", "publicada")
list_editable = ("autor",)
```

O Django gera erro porque um campo em `list_editable` precisa obrigatoriamente estar presente em `list_display`.

## 🔄 Formas equivalentes de registro

As duas abordagens abaixo produzem o mesmo resultado:

### ✅ Decorador — recomendado

```python
@admin.register(Receita)
class ReceitaAdmin(admin.ModelAdmin):
    list_display = ("titulo", "autor")
```

### ✅ Registro tradicional

```python
class ReceitaAdmin(admin.ModelAdmin):
    list_display = ("titulo", "autor")


admin.site.register(Receita, ReceitaAdmin)
```

### 📌 Quando usar cada forma?

- Use `@admin.register(Modelo)` na maioria dos casos: é mais limpo e mantém a configuração junto à classe.
- Use `admin.site.register()` quando precisar registrar condicionalmente, registrar vários modelos de uma vez ou trabalhar com um `AdminSite` customizado.

## 🏷️ A importância do `__str__`

O método `__str__` define como um objeto será representado como texto. O Django Admin usa esse retorno em listagens, relacionamentos e mensagens do sistema.

```python
# receitas/models.py

class Categoria(models.Model):
    nome = models.CharField(max_length=100)

    def __str__(self):
        # Exibe o nome da categoria no Admin,
        # por exemplo: "Sobremesas"
        return self.nome


class Receita(models.Model):
    titulo = models.CharField(max_length=200)

    def __str__(self):
        # Exibe o título da receita no Admin,
        # por exemplo: "Bolo de chocolate"
        return self.titulo
```

Sem `__str__`, o Admin pode exibir representações pouco úteis, como:

```text
Receita object (1)
Categoria object (3)
```

Com `__str__`, a interface fica clara e profissional.

## 🔗 Campos `ManyToManyField` no Admin

No modelo `Receita`, o campo `categorias` é um `ManyToManyField`. O Django Admin já cria automaticamente um widget de seleção múltipla.

```python
categorias = models.ManyToManyField(Categoria)
```

Isso permite associar uma receita a várias categorias, como:

- “Sobremesas”
- “Vegetariano”
- “Rápido”

Para poucas categorias, o widget padrão é suficiente. Para muitas opções, vale melhorar a experiência com `filter_horizontal` ou bibliotecas como `django-select2`.

### ✅ Opção nativa: `filter_horizontal`

```python
@admin.register(Receita)
class ReceitaAdmin(admin.ModelAdmin):
    # Cria uma interface de dupla lista para o campo ManyToMany.
    # Facilita localizar e mover categorias entre
    # "disponíveis" e "selecionadas".
    filter_horizontal = ("categorias",)
```

Essa é geralmente a melhor primeira escolha, pois não exige instalar pacotes externos.

***

## 🔎 Melhorando `ManyToManyField` com `django-select2`

Se sua aplicação tiver muitas categorias, o widget padrão pode ficar difícil de usar. O `django-select2` adiciona busca e seleção mais amigável.

### 1️⃣ Instalação

```bash
pip install django-select2
```

### 2️⃣ Configuração

```python
# settings.py

INSTALLED_APPS = [
    # ...

    # Deve ficar antes de django.contrib.admin
    # para que o tema/estilos sejam aplicados corretamente.
    "django_select2",

    "django.contrib.admin",
    # ...
]
```

### 3️⃣ Uso no Admin

```python
# receitas/admin.py

from django.contrib import admin
from django.db import models

# Importa o widget Select2 para campos de seleção múltipla.
from django_select2.forms import Select2MultipleWidget

from .models import Categoria, Receita


@admin.register(Receita)
class ReceitaAdmin(admin.ModelAdmin):
    list_display = (
        "titulo",
        "autor",
        "publicada",
    )

    # Substitui o widget padrão de todos os ManyToManyField
    # do formulário de Receita pelo Select2MultipleWidget.
    formfield_overrides = {
        models.ManyToManyField: {
            "widget": Select2MultipleWidget,
        },
    }
```

### 🔍 Explicação

- `formfield_overrides` permite substituir o widget padrão usado pelo Admin para determinado tipo de campo.
- `models.ManyToManyField` é a chave que identifica o tipo de campo.
- `Select2MultipleWidget` cria uma caixa com busca, útil quando existem muitas opções.

⚠️ **Cuidado:** `formfield_overrides` afeta **todos** os `ManyToManyField` daquele formulário. Se houver vários relacionamentos e você quiser alterar apenas `categorias`, prefira um `ModelForm` personalizado.

## 🎨 Temas de terceiros

O Admin padrão do Django é funcional, seguro e bem integrado ao framework. Para melhorar o visual, você pode usar pacotes de terceiros.

| Pacote | Característica |
|---|---|
| `django-jazzmin` | Interface moderna, responsiva e altamente configurável |
| `django-admin-adminlte` | Visual baseado no template AdminLTE |

Exemplo com `django-jazzmin`:

```bash
pip install django-jazzmin
```

```python
# settings.py

INSTALLED_APPS = [
    # O tema deve vir antes do admin.
    "jazzmin",

    "django.contrib.admin",
    # ...
]
```

⚠️ **Recomendação didática:** comece usando o Admin padrão. Domine `ModelAdmin`, `list_display`, filtros, busca e permissões antes de adicionar temas. O tema muda a aparência, mas não substitui uma boa organização do painel.

## 🧾 Versão final recomendada do `admin.py`

```python
# receitas/admin.py

from django.contrib import admin
from .models import Categoria, Receita


# Registro simples: suficiente para categorias.
admin.site.register(Categoria)


# Registro personalizado para receitas.
@admin.register(Receita)
class ReceitaAdmin(admin.ModelAdmin):
    """
    Configura a exibição e a edição de Receita no Django Admin.
    """

    # Colunas exibidas na listagem.
    list_display = (
        "titulo",
        "autor",
        "tempo_preparo",
        "publicada",
        "data_publicacao",
    )

    # Filtros laterais.
    list_filter = (
        "publicada",
        "autor",
        "categorias",
        "data_publicacao",
    )

    # Campos pesquisáveis.
    search_fields = (
        "titulo",
        "ingredientes",
        "modo_preparo",
    )

    # Campo editável diretamente na listagem.
    list_editable = (
        "publicada",
    )

    # Melhora a seleção de categorias.
    filter_horizontal = (
        "categorias",
    )

    # Evita select muito grande quando há muitos autores.
    raw_id_fields = (
        "autor",
    )
```

## 📚 Resumo

- O Django Admin só exibe modelos **registrados** em `admin.py`.
- `admin.site.register(Modelo)` é ideal para registros simples.
- `@admin.register(Modelo)` com uma classe `ModelAdmin` é a abordagem recomendada para personalização.
- `list_display`, `list_filter`, `search_fields` e `list_editable` melhoram muito a produtividade administrativa.
- `__str__` é essencial para exibir objetos de forma legível.
- Para `ManyToManyField`, comece com `filter_horizontal`; use `django-select2` apenas se a experiência padrão não for suficiente.

O Django 6.1 mantém a API `AdminSite.register()` com suporte a modelo único, lista de modelos, classe `ModelAdmin` opcional e opções diretas; ele levanta `AlreadyRegistered` caso o modelo já tenha sido registrado. [docs.djangoproject](https://docs.djangoproject.com/en/6.1/ref/contrib/admin/)
