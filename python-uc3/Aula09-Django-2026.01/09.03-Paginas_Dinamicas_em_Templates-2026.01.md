# 🍳 Aula 09.03 — Páginas Dinâmicas em Templates Django

O objetivo das páginas dinâmicas é exibir **dados específicos de um objeto** — por exemplo, uma única receita — reutilizando **um único template**. Para isso, combinamos três elementos: uma **`URL dinâmica`**, uma **`view`** que consulta o banco de dados e um **`template Django`** que renderiza as informações. 

## 1. O que você vai construir

Criaremos a página **Detalhe da Receita**, acessível por uma URL como:

```text
/receita/3/
```

Nessa URL:

- `receita/` é o prefixo fixo da rota.
- `3` é o `pk` (*primary key*) da receita.
- A `view` busca a receita correspondente no banco e envia o objeto ao `template`.
- O `template` exibe título, ingredientes, modo de preparo, autor e categorias.

O Django oferece conversores de `URL` nativos, como `int` e `slug`; o `int` captura um número inteiro e o `slug` captura textos amigáveis como `pao-de-queijo-simples`.

## 🗃️ Passo 2 — Criar o modelo `Receita`

Abra `receitas/models.py` e escreva:

```python
# receitas/models.py

from django.contrib.auth.models import User
from django.db import models


class Categoria(models.Model):
    """Representa uma categoria de receita, como Sobremesa ou Jantar."""

    nome = models.CharField(max_length=100)

    class Meta:
        verbose_name = "Categoria"
        verbose_name_plural = "Categorias"
        ordering = ["nome"]

    def __str__(self):
        return self.nome


class Receita(models.Model):
    """Representa uma receita publicada no sistema."""

    titulo = models.CharField(max_length=200)

    ingredientes = models.TextField(
        help_text="Informe um ingrediente por linha."
    )

    modo_preparo = models.TextField(
        help_text="Descreva o passo a passo do preparo."
    )

    tempo_preparo = models.PositiveIntegerField(
        help_text="Tempo total de preparo, em minutos."
    )

    data_publicacao = models.DateTimeField(auto_now_add=True)

    publicada = models.BooleanField(default=False)

    # Relação N:N: uma receita pode ter várias categorias
    # e uma categoria pode estar em várias receitas.
    categorias = models.ManyToManyField(
        Categoria,
        related_name="receitas",
        blank=True,
    )

    # Relação 1:N: cada receita pertence a um autor.
    autor = models.ForeignKey(
        User,
        on_delete=models.CASCADE,
        related_name="receitas",
    )

    class Meta:
        verbose_name = "Receita"
        verbose_name_plural = "Receitas"
        ordering = ["-data_publicacao"]

    def __str__(self):
        return self.titulo
```

Se o seu projeto fosse uma casa, o **Model** seria a planta do arquiteto. É ele que diz ao Django como o nosso banco de dados deve ser construído.

### 2.1. Os Imports

```python
from django.contrib.auth.models import User
from django.db import models
```

*   **`models`**: É a "caixa de ferramentas" padrão do Django para criar tabelas no banco de dados.

*   **`User`**: Importamos o modelo de usuário padrão do Django. Faremos isso porque toda receita precisa ter um "dono" (o autor que a publicou).

### 2.2. O Model `Categoria` 

O modelo cria uma tabela no banco de dados chamada `Categoria` com apenas uma coluna de texto.

*   **`nome = models.CharField(max_length=100)`**: Cria uma coluna de texto (VARCHAR no banco) que aceita no máximo 100 caracteres.
  
*   **`class Meta`**: Esta classe interna não cria colunas no banco. Ela serve para dar **configurações extras** ao modelo.
  
    *   `verbose_name` e `verbose_name_plural`: Define como o nome aparecerá no Painel Administrativo do Django.

    *   `ordering = ["nome"]`: Garante que, sempre que listarmos as categorias, elas venham em **ordem alfabética**.
  
*   **`def __str__(self)`**: É a "etiqueta" do objeto. Quando o Django precisar mostrar essa categoria no admin ou no terminal, ele mostrará o `nome` (ex: "Sobremesa"), e não um código estranho como `Categoria object (1)`.

### 2.3. O Model `Receita` 

Vamos analisar os campos e, principalmente, os **relacionamentos**.

#### A. Campos Básicos e Dicas de Preenchimento

*   **`titulo`**: Texto curto (200 caracteres).

*   **`ingredientes` e `modo_preparo`**: Usamos `TextField` porque são textos longos. 

*   **`help_text`**: Quando formos criar o formulário HTML, o Django usará esse texto como uma "dica" (placeholder ou texto de ajuda) para o usuário saber exatamente como preencher.

*   **`tempo_preparo`**: `PositiveIntegerField` garante que o usuário não possa cadastrar um tempo negativo (ninguém faz uma receita em -10 minutos!).

*   **`data_publicacao`**: `DateTimeField` com **`auto_now_add=True`**. 
    *  Isso significa que o Django vai pegar a data e hora exatas do servidor no momento em que a receita for salva pela primeira vez e preencherá automaticamente.

*   **`publicada`**: `BooleanField` (Verdadeiro/Falso). O `default=False` significa que, ao criar uma receita, ela já nasce como "rascunho" (não publicada).

#### B. Os Relacionamentos

É aqui que os modelos conversam entre si.

**1. Relação 1:N (Um para Muitos) - `autor`**

```python
autor = models.ForeignKey(User, on_delete=models.CASCADE, related_name="receitas")

```

Um Autor (`User`) pode ter **Muitas** Receitas. Mas uma Receita só pode ter **Um** Autor.

*   **`ForeignKey`**: Cria uma chave estrangeira no banco.

*   **`on_delete=models.CASCADE`**: Regra de segurança. Se o Autor for deletado do sistema, todas as receitas dele serão deletadas em cascata junto com ele.

*   **`related_name="receitas"`**: Permite o "caminho inverso". Se eu tiver um objeto `autor`, posso descobrir todas as receitas dele digitando `autor.receitas.all()`.

**2. Relação N:N (Muitos para Muitos) - `categorias`**
```python
categorias = models.ManyToManyField(Categoria, related_name="receitas", blank=True)
```
Uma Receita pode ter **Várias** Categorias (ex: "Jantar" e "Rápido"). E uma Categoria pode estar em **Várias** Receitas.

*   **`ManyToManyField`**: O Django cria uma "tabela intermediária" invisível no banco de dados para gerenciar essas ligações.

*   **`blank=True`**: Permite que, no formulário, o usuário salve a receita sem selecionar nenhuma categoria (campo opcional). Isso é apenas para o formulário, o banco de dados em si sempre exige o campo.

*   **`related_name="receitas"`**: Caminho inverso. Se eu tiver um objeto `categoria`, posso listar todas as receitas dela usando `categoria.receitas.all()`.

#### C. Meta e __str__ da Receita

*   **`ordering = ["-data_publicacao"]`**: O sinal de **menos (`-`)** é o truque do Django para dizer "ordem decrescente". Ou seja, as receitas mais recentes aparecerão sempre no topo da lista!

*   **`__str__`**: Retorna o `titulo` da receita.

### 2.4. Aplicar as migrações

```bash
python manage.py makemigrations receitas
python manage.py migrate
```

> 💡 **Por que `PositiveIntegerField`?**  
> ---
> - O tempo de preparo nunca deve ser negativo. 
> - Esse campo aceita apenas valores iguais ou maiores que zero, tornando o modelo mais seguro.

## Passo 3 - Registrando os Modelos no Admin (`admin.py`)

Criar o `models.py` é como projetar a planta da casa. Agora precisamos "mobiliar" essa casa para que possamos gerenciá-la visualmente através do **Django Admin** — aquela interface administrativa pronta que o Django nos dá de graça!

Para isso, editamos o arquivo `receitas/admin.py`:

```python
# receitas/admin.py

from django.contrib import admin
from .models import Categoria, Receita


@admin.register(Categoria)
class CategoriaAdmin(admin.ModelAdmin):
    """Configuração administrativa para o modelo Categoria."""

    list_display = ["nome"]
    search_fields = ["nome"]
    ordering = ["nome"]


@admin.register(Receita)
class ReceitaAdmin(admin.ModelAdmin):
    """Configuração administrativa para o modelo Receita."""

    list_display = [
        "titulo",
        "autor",
        "tempo_preparo",
        "publicada",
        "data_publicacao",
    ]
    
    list_filter = ["publicada", "categorias", "data_publicacao"]
    
    search_fields = ["titulo", "ingredientes", "modo_preparo"]
    
    filter_horizontal = ["categorias"]
    
    readonly_fields = ["data_publicacao"]
    
    ordering = ["-data_publicacao"]
    
    list_editable = ["publicada"]
```

### 3.1. Entendendo Cada Parte do `admin.py`

#### 3.1.1 O Decorator `@admin.register(Model)`

```python
@admin.register(Categoria)
class CategoriaAdmin(admin.ModelAdmin):
```

*   **O que é:** É uma forma moderna e elegante de dizer ao Django: "Ei, quero que o modelo `Categoria` apareça no Admin, e use esta classe `CategoriaAdmin` para configurá-lo".
*   **Alternativa antiga:** Você pode ter visto em tutoriais mais antigos o uso de `admin.site.register(Categoria, CategoriaAdmin)`. O decorator `@admin.register` faz a mesma coisa, mas é mais legível e recomendado atualmente.

#### 3.1.2  `list_display` — O que aparece na lista?

```python
list_display = ["titulo", "autor", "tempo_preparo", "publicada", "data_publicacao"]
```

*   **Conceito:** Define quais colunas aparecerão quando você abrir a lista de receitas no admin.
*   **Sem isso:** O Django mostraria apenas `Receita object (1)`, `Receita object (2)`... inútil!
*   **Com isso:** Você vê uma tabela bonita com o título, quem criou, tempo de preparo, se está publicada e a data.

#### 3.1.3. `list_filter` — Filtros laterais

```python
list_filter = ["publicada", "categorias", "data_publicacao"]
```
*   **Conceito:** Cria uma barra lateral direita com filtros rápidos.
*   **Na prática:** Aparecerão caixas para você filtrar receitas por:
    *   Status (Publicada/Não publicada)
    *   Categoria (Sobremesa, Jantar, etc.)
    *   Data (Hoje, Esta semana, Este mês...)

#### 3.1.4. `search_fields` — A barra de busca
```python
search_fields = ["titulo", "ingredientes", "modo_preparo"]
```
*   **Conceito:** Adiciona uma barra de busca no topo da lista.
*   **Na prática:** O usuário pode digitar "chocolate" e o Django vai buscar no título, nos ingredientes e no modo de preparo. Ele usa o operador `LIKE` do banco de dados automaticamente!

#### 3.1.5. `filter_horizontal` — O Super Poder para ManyToMany! ⭐
```python
filter_horizontal = ["categorias"]
```
*   **Conceito:** Transforma o campo `ManyToManyField` (que seria um `<select multiple>` horrível) em uma interface linda com duas caixas lado a lado.
*   **Na prática:** 
    *   Caixa esquerda: todas as categorias disponíveis
    *   Caixa direita: categorias já selecionadas para esta receita
    *   Botões no meio para mover itens entre as caixas
    *   Barra de busca dentro da caixa para filtrar categorias
*   **Por que é importante:** Lembra do `django-select2` que mencionei? O `filter_horizontal` é a solução nativa do Django para isso. Se quiser algo ainda mais customizado, aí sim usamos o `django-select2` nos formulários do frontend.

#### 3.1.6. `readonly_fields` — Campos que não podem ser editados
```python
readonly_fields = ["data_publicacao"]
```
*   **Conceito:** Exibe o campo na tela de edição, mas impede que o usuário o altere.
*   **Por que usar:** A `data_publicacao` é preenchida automaticamente pelo Django (`auto_now_add=True`). Não faz sentido o usuário tentar mudá-la manualmente.

#### 3.1.7. `list_editable` — Edição rápida na lista
```python
list_editable = ["publicada"]
```
*   **Conceito:** Permite editar o campo diretamente na lista, sem precisar entrar na tela de detalhes.
*   **Na prática:** Aparece um checkbox na listagem ao lado de cada receita. Você pode marcar várias receitas como "publicadas" e salvar de uma vez só!

#### 💡 Observações Adicionais 

1. **Personalização Visual com Jazzmin ou AdminLTE:**
   O `Django Admin` padrão é funcional, mas básico. Se você quiser uma interface mais moderna e profissional, pode instalar o **`django-jazzmin`** ou **`django-admin-adminlte`**. Eles mudam completamente o visual do admin, deixando-o com cara de dashboard moderno, usando Bootstrap e temas personalizáveis.

2. **Acessando Dados via Admin:**
   Uma vez registrado, você pode:
   *   Criar novas categorias e receitas
   *   Editar receitas existentes
   *   Deletar registros
   *   Exportar dados (com plugins adicionais)
   *   Tudo isso sem escrever uma linha de SQL!

3. **Relacionamentos no Admin:**
   Note que ao criar uma receita, o campo `autor` aparecerá como um dropdown com todos os usuários do sistema. E o campo `categorias` aparecerá com aquela interface bonita do `filter_horizontal`. O Django gerencia toda a complexidade dos relacionamentos automaticamente!

## ⚙️ Passo 4 — Criar as views dinâmicas

Abra `receitas/views.py`:

```python
# receitas/views.py

from django.shortcuts import get_object_or_404, render

from .models import Receita


def lista_receitas(request):
    """Exibe todas as receitas publicadas, das mais recentes para as mais antigas."""

    receitas = Receita.objects.filter(publicada=True)

    context = {
        "receitas": receitas,
    }

    return render(request, "receitas/lista.html", context)


def detalhe_receita(request, pk):
    """
    Exibe os detalhes de uma receita específica.

    O parâmetro 'pk' vem da URL dinâmica:
    /receita/<int:pk>/
    """

    # Busca a receita pelo ID e exige que ela esteja publicada.
    # Se não existir, o Django retorna automaticamente um erro 404.
    receita = get_object_or_404(
        Receita,
        pk=pk,
        publicada=True,
    )

    context = {
        "receita": receita,
    }

    return render(request, "receitas/detalhe.html", context)
```

### 4.1. 🔍 Por que usar `get_object_or_404`?

A função `get_object_or_404()` busca um objeto usando os filtros informados. Se nenhum objeto for encontrado, ela lança um `Http404`, retornando a página padrão de “não encontrado”. 

```python
# ❌ Evite este padrão em views simples:
receita = Receita.objects.get(pk=pk)

# ✅ Prefira este padrão:
receita = get_object_or_404(Receita, pk=pk)
```

Sem `get_object_or_404`, um acesso a `/receita/9999/` — quando a receita não existe — pode gerar um erro interno no servidor. Com ela, o comportamento correto é retornar **404 Not Found**.

## 🧭 `pk` ou `slug`: qual usar?

| Critério | `pk` | `slug` |
|---|---|---|
| Exemplo de URL | `/receita/3/` | `/receita/pao-de-queijo-simples/` |
| Implementação | Mais simples | Exige campo extra no modelo |
| Legibilidade | Baixa | Alta |
| SEO | Neutro | Melhor para URLs públicas |
| Indicado para | Sistemas internos, admin, APIs | Blogs, catálogos, sites públicos |

O conversor `slug` aceita letras, números, hífen e underline, como em `pao-de-queijo-simples`. 

### 5.1. Exemplo com `slug`

Adicione o campo ao modelo:

```python
# receitas/models.py

from django.utils.text import slugify


class Receita(models.Model):
    # ... outros campos ...

    slug = models.SlugField(
        max_length=200,
        unique=True,
        blank=True,
    )

    def save(self, *args, **kwargs):
        # Gera automaticamente o slug a partir do título,
        # caso ele ainda não tenha sido definido.
        if not self.slug:
            self.slug = slugify(self.titulo)

        super().save(*args, **kwargs)
```

Altere a URL:

```python
# receitas/urls.py

path(
    "receita/<slug:slug>/",
    views.detalhe_receita,
    name="detalhe_receita",
),
```

E altere a view:

```python
# receitas/views.py

def detalhe_receita(request, slug):
    receita = get_object_or_404(
        Receita,
        slug=slug,
        publicada=True,
    )

    return render(
        request,
        "receitas/detalhe.html",
        {"receita": receita},
    )
```

> ⚠️ **Importante:** 
> --- 
> - Após adicionar o campo `slug`, execute novamente `makemigrations` e `migrate`.


## 🧩 Dica: `django-select2` para categorias

Para melhorar a seleção de várias categorias no Django Admin, você pode usar o `django-select2`, que oferece um campo pesquisável. Instale com:

```bash
pip install django-select2
```

Adicione em `config/settings.py`:

```python
INSTALLED_APPS = [
    # ... outras aplicações ...
    "django_select2",
]
```

No `receitas/admin.py`:

```python
# receitas/admin.py

from django.contrib import admin
from django.db import models
from django_select2.forms import Select2MultipleWidget

from .models import Categoria, Receita


@admin.register(Categoria)
class CategoriaAdmin(admin.ModelAdmin):
    list_display = ("nome",)


@admin.register(Receita)
class ReceitaAdmin(admin.ModelAdmin):
    list_display = ("titulo", "autor", "publicada", "data_publicacao")
    list_filter = ("publicada", "categorias")
    search_fields = ("titulo", "ingredientes")

    # Melhora a seleção de categorias com um campo pesquisável.
    formfield_overrides = {
        models.ManyToManyField: {
            "widget": Select2MultipleWidget
        },
    }
```
