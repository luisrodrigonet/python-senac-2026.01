# 🦖 Aula 08 — Páginas Estáticas, Dinâmicas e Navegação com Links

Nesta aula, você vai entender **por que sites como o Senac RJ precisam de um `backend` como o `Django`** e, em seguida, planejar os **links de navegação** da aplicação do grupo. A ideia central é simples: páginas estáticas são arquivos fixos; páginas dinâmicas são montadas no servidor a partir de dados armazenados em um banco. 

## 1. Objetivos da aula 

- Diferenciar páginas **estáticas** de páginas **dinâmicas**.
- Compreender como o Django usa **URLs, views e templates** para gerar páginas.
- Perceber a diferença prática na **manutenção** de um site.
- Propor uma estrutura de navegação com links claros para o projeto do grupo.

## 2. O que é uma página estática?

Uma página estática é aquela cujo conteúdo já está praticamente definido nos arquivos `HTML`, `CSS` e `JavaScript` enviados pelo servidor. Ela pode continuar tendo pequenas interações no navegador, mas o texto principal, as seções e os `links` normalmente não mudam sem que alguém edite o código.

### 2.1.  Atividade prática 🧪

1. Acesse um site institucional simples, uma documentação ou uma página de um projeto de código aberto.
2. Clique com o botão direito e escolha **“Inspecionar”** ou **“Exibir código-fonte da página”**.
3. **Observe o HTML**: títulos, parágrafos, imagens e links estão diretamente presentes no código recebido pelo navegador.

> 🎯 **Reflexão:** 
> - se a empresa quiser trocar um parágrafo, um telefone ou uma data, alguém precisará editar o arquivo HTML e publicar novamente o site.

## 3. O que é uma página dinâmica?

Uma página dinâmica é gerada no momento em que o usuário faz a requisição. O servidor busca informações — por exemplo, cursos, turmas, preços, datas e disponibilidade — em um banco de dados e preenche um template HTML com esses dados.

O portal de cursos do Senac RJ é um bom exemplo: ele exibe cursos por área, unidade, modalidade, carga horária e próximas turmas. Essas informações mudam com frequência e não faz sentido manter cada página de curso escrita manualmente em HTML. [rj.senac](https://www.rj.senac.br/)

### 🔁 Fluxo do Django

```text
Usuário acessa /cursos/
        ↓
Django identifica a URL
        ↓
A view consulta o banco de dados pelo ORM
        ↓
Os dados são enviados ao template
        ↓
O template é renderizado
        ↓
O HTML final chega ao navegador
```

No Django, a **`URLconf`** mapeia caminhos como `/cursos/` para uma **`view`**; a view recupera dados e renderiza um `template`. 

### 💡 Exemplo didático

- `views.py`

```python
# cursos/views.py
from django.shortcuts import render
from .models import Curso  # Modelo que representa a tabela "Curso" no banco

def lista_cursos(request):
    # O ORM busca todos os cursos cadastrados no banco de dados
    cursos = Curso.objects.all()

    # O template recebe os dados e monta a página HTML
    return render(request, "cursos/lista.html", {"cursos": cursos})
```

- `cursos/templates/cursos/lista.html`

```html
<!-- cursos/templates/cursos/lista.html -->
<h1>📚 Cursos disponíveis</h1>

<!-- O loop percorre os cursos vindos do banco de dados -->
{% for curso in cursos %}
  <article>
    <h2>{{ curso.titulo }}</h2>
    <p>{{ curso.descricao }}</p>
    <p>⏱️ Carga horária: {{ curso.carga_horaria }} horas</p>
  </article>
{% empty %}
  <p>Nenhum curso cadastrado ainda.</p>
{% endfor %}
```

Com esse padrão, **um único template** consegue exibir 10, 100 ou 1.000 cursos. 

> O que muda não é o código HTML, mas os registros do banco de dados.


## 4. Estático x dinâmico: manutenção

| Característica | Página estática | Página dinâmica com Django |
|---|---|---|
| 📄 **Conteúdo** | Escrito diretamente no `HTML`. | Armazenado no banco de dados. |
| ✏️ **Atualização** | Exige edição de código e novo deploy. | Feita pelo Django Admin, sem alterar código. |
| 📈 **Escalabilidade** | `Baixa`: cada novo item pode exigir nova página. | `Alta`: cada item é apenas um novo registro. |
| 🧑‍💻 **Quem atualiza** | Normalmente, um desenvolvedor. | Administradores, editores ou equipe comercial. |
| 🛠️ **Ferramentas** | Editor de código, FTP, deploy manual. | Django, ORM, templates, banco de dados e painel administrativo. |

### 4.1.  Recursos úteis no ecossistema Django

- **`Django Admin`:** painel para **criar**, **editar** e **remover** registros sem programar.
- **`django-jazzmin` ou `django-admin-adminlte`:** melhoram a aparência e a usabilidade do painel administrativo.
- **`django-dbbackup`:** ajuda a realizar **backup** e **restauração** do banco de dados.
- **PostgreSQL com `psycopg2-binary`:** banco relacional robusto, muito usado em projetos Django.

> 🟥 **Atenção:** 
> - O conteúdo dinâmico vive no banco de dados. 
> - Por isso, backups regulares são parte essencial da manutenção.

## 5. Páginas e links: a navegação do projeto

**`Links`** são a forma de **conectar as páginas** da aplicação. Sem eles, o usuário precisa digitar endereços manualmente, o que torna a experiência confusa e pouco profissional.

No `Django`, devemos usar a tag `{% url %}` em vez de escrever caminhos fixos como `href="/cursos/"`. Assim, se a **URL mudar** no futuro, os **links continuam funcionando**. 

### 5.1 Exemplo de menu

- `templates/base.html`

```html
<!-- templates/base.html -->
<nav>
  <!-- O nome "home", "cursos" etc. deve existir no urls.py -->
  <a href="{% url 'home' %}">🏠 Início</a>
  <a href="{% url 'cursos' %}">📚 Cursos</a>
  <a href="{% url 'sobre' %}">ℹ️ Sobre nós</a>
  <a href="{% url 'contato' %}">✉️ Fale conosco</a>
</nav>
```

- `core/urls.py`

```python
# core/urls.py
from django.urls import path
from . import views

urlpatterns = [
    # Cada URL recebe um "name", usado pelos links do template
    path("", views.home, name="home"),
    path("cursos/", views.lista_cursos, name="cursos"),
    path("sobre/", views.sobre, name="sobre"),
    path("contato/", views.contato, name="contato"),
]
```

## 6.  Atividade em grupo: proposta de navegação 

A empresa contratante solicitou que a aplicação possua **links** para navegar entre suas páginas. Seu grupo deve pesquisar, discutir e apresentar uma proposta de menu.

### 6.1  Instruções 🏋️

1. **Pesquisem referências:** analisem os sites do Senac, Sesc e outras instituições. Observe quais páginas aparecem no menu principal e como os títulos são organizados. O Senac RJ, por exemplo, destaca acesso rápido, cursos por área e informações institucionais. [rj.senac](https://www.rj.senac.br/)
2. **Listem as páginas essenciais:** pense nas informações que o usuário precisa encontrar facilmente.
3. **Definam os títulos dos links:** usem linguagem curta, clara e voltada para o usuário.
4. **Organizem a hierarquia:** decidam o que fica no menu principal e o que pode ficar no rodapé.
5. **Registrem a proposta:** cada integrante deve enviar a pesquisa e a proposta pelo Teams.

### 6.2. Exemplo de proposta ✅

| Link do menu | Página | Finalidade |
