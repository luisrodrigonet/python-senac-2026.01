# 📊 Slide de Resumo — Projeto Inicial em Django

## 1. Django: Projeto e Aplicação

- **Projeto** (`config`): guarda as **configurações** globais, **URLs** principais e configurações do site.
- **Aplicação** (`paginas`): módulo responsável por uma parte específica do sistema.
- Uma view recebe a requisição e retorna uma resposta; o `URLconf` **liga caminhos** de URL às views. 

```bash
django-admin startproject config .
python manage.py startapp paginas
```

## 2. Configuração essencial

```python
INSTALLED_APPS = [
    # apps padrão do Django
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",
    "django.contrib.staticfiles",

    # app do projeto
    "paginas",   # <-- Habilitando a aplicação paginas
]
```

- Sem registrar a app em `INSTALLED_APPS`, o Django não reconhece seus templates, models e configurações. 
- Para templates globais, configure `DIRS: [BASE_DIR / "templates"]` e mantenha `APP_DIRS: True`.

## 3. Fluxo de uma requisição

```text
Navegador → URL → URLconf → View → Template → HTML → Navegador
```

1. O usuário acessa, por exemplo, `/sobre/`.
2. O Django procura a rota em `urlpatterns`.
3. A rota chama a `view` correspondente.
4. A `view` renderiza o template e devolve o HTML. 

## 4. URLs nomeadas

```python
app_name = "paginas"

urlpatterns = [
    path("", views.home, name="home"),
    path("sobre/", views.sobre, name="sobre"),
]
```

```html
<a href="{% url 'paginas:sobre' %}">Sobre</a>
```

- `app_name` cria o namespace da aplicação.
- `name` identifica a rota.
- `{% url %}` gera o **link** dinamicamente, evitando **URLs** fixas no HTML.

## 5. Templates com herança

```html
{% extends "base.html" %}

{% block title %}Home{% endblock title %}

{% block content %}
    <h1>Bem-vindo!</h1>
{% endblock content %}
```

- `base.html` contem o menu, rodapé, CSS e JavaScript.
- `{% block %}` **define áreas** que cada página pode substituir.
- A **herança evita repetir** a mesma estrutura HTML em todas as páginas. 

## ✅ Resumo em uma frase

> Um projeto Django conecta **URLs → views → templates**, enquanto as aplicações organizam o código em módulos reutilizáveis.
