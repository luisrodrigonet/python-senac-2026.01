# 🎓 Projeto Inicial em Django

Django organiza um site em **projeto** (configurações globais) e **aplicações** (módulos funcionais). Uma `view` recebe a requisição, escolhe um template e retorna uma resposta HTTP; o URLconf conecta caminhos de URL às views. 

## 1.  Objetivos de aprendizagem 🎯

Ao final da aula, o estudante será capaz de:

- Criar um projeto `Django` e uma aplicação com `startproject` e `startapp`.
- Registrar a aplicação em `INSTALLED_APPS`.
- Criar *function-based views* para páginas estáticas.
- Configurar `URLs` do projeto e da aplicação.
- Criar `templates` com herança usando `base.html`.
- Utilizar `links` dinâmicos com `{% url %}`.
- Executar o servidor de desenvolvimento e testar as páginas.

## 2.  Conceitos-chave 🧠

| Conceito | Definição simples |
| :--- | :--- |
| `Projeto` | Conjunto de configurações e aplicações de um site Django.   |
| `Aplicação` | Módulo reutilizável com views, models, templates e URLs.   |
| `View` | Função Python que recebe uma requisição e retorna uma resposta.  |
| `URLconf` | Mapeamento entre caminhos de URL e views.   |
| `Template` | Arquivo HTML com marcações Django para exibir dados dinâmicos.   |
| `Herança de templates `| Técnica para reaproveitar cabeçalho, menu e rodapé com `base.html`. |
| `Namespace de URL` | Prefixo que evita conflitos de nomes entre apps, como `paginas:home`.  |

## 4. Parte 1 — Criar projeto e aplicação 🏗️

Com o ambiente virtual ativado, execute:

```bash
django-admin startproject core .
python manage.py startapp paginas
```

- `core` é o **projeto**: contém `settings.py`, `urls.py` e configurações globais.
- `paginas` é a **aplicação**: conterá as views e templates das páginas simples.
- O ponto final em `config .` cria os arquivos na pasta atual, em vez de criar uma subpasta extra. 

Estrutura inicial:

```text
projeto-basico/
├── core/
│   ├── settings.py
│   └── urls.py
├──paginas/
│   ├── views.py
│   └── ...
├── manage.py
└── requirements.txt
```

## 5. Parte 2 — Registrar a aplicação ⚙️

Abra `config/settings.py` e localize `INSTALLED_APPS`. Adicione `paginas` ao final da lista:

```python
# config/settings.py

INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",
    "django.contrib.staticfiles",

    "paginas",
]
```

Sem registrar a aplicação, o Django não reconhece seus modelos, templates ou comandos relacionados. `INSTALLED_APPS` é a lista oficial de aplicações ativas no projeto. 

### 5.1. Explicação dos apps padrão

| App | Função |
| :--- | :--- |
| `django.contrib.admin` | Painel administrativo.   |
| `django.contrib.auth` | Usuários, grupos, permissões e autenticação.  |
| `django.contrib.contenttypes` | Registro de modelos e suporte a permissões genéricas. |
| `django.contrib.sessions` | Dados de sessão entre requisições. |
| `django.contrib.messages` | Mensagens temporárias para o usuário. |
| `django.contrib.staticfiles` | Gerenciamento de arquivos estáticos. |

## 6.  Parte 3 — Configurar templates globais 🧩

Para usar um `base.html` compartilhado por todas as páginas, localize `TEMPLATES` em `config/settings.py` e ajuste `DIRS`:

```python
# core/settings.py

from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent.parent

TEMPLATES = [
    {
        "BACKEND": "django.template.backends.django.DjangoTemplates",
        "DIRS": [BASE_DIR / "templates"],
        "APP_DIRS": True,
        "OPTIONS": {
            "context_processors": [
                "django.template.context_processors.request",
                "django.contrib.auth.context_processors.auth",
                "django.contrib.messages.context_processors.messages",
            ],
        },
    },
]
```

- `DIRS`: informa ao Django onde procurar templates globais, como `templates/base.html`.
- `APP_DIRS: True`: permite encontrar templates dentro das aplicações registradas.
- O Django percorre os diretórios configurados até encontrar o template solicitado. 

## 7. Parte 4 — Criar as views 👀

Abra `paginas/views.py` e substitua o conteúdo por:

```python
# paginas/views.py

from django.shortcuts import render


def home(request):
    return render(
        request,
        "paginas/home.html",
        {"titulo": "Página Inicial"},
    )


def sobre(request):
    return render(
        request,
        "paginas/sobre.html",
        {"titulo": "Sobre Nós"},
    )


def politica_privacidade(request):
    return render(
        request,
        "paginas/politica_privacidade.html",
        {"titulo": "Política de Privacidade"},
    )
```

A função `render()` recebe:

1. O objeto `request`.
2. O **caminho** do `template`.
3. Um **dicionário de contexto**, com variáveis disponíveis no HTML. 

Aqui, `{{ titulo }}` será substituído pelo valor enviado pela view.

## 8 Parte 5 — Criar as URLs da aplicação

Crie o arquivo `paginas/urls.py`:

```python
# paginas/urls.py

from django.urls import path

from . import views

app_name = "paginas"

urlpatterns = [
    path("", views.home, name="home"),
    path("sobre/", views.sobre, name="sobre"),
    path(
        "politica-privacidade/",
        views.politica_privacidade,
        name="politica_privacidade",
    ),
]
```

Cada `path()` possui três partes principais:

| Parte | Exemplo | Função |
| :--- | :--- | :--- |
| Caminho | `"sobre/"` | URL acessada no navegador. |
| View | `views.sobre` | Função executada. |
| Nome | `name="sobre"` | Referência usada nos templates. |

O `app_name = "paginas"` cria o namespace da aplicação. Isso permite chamar as rotas como `paginas:home`, `paginas:sobre` e `paginas:politica_privacidade`. [django.readthedocs](https://django.readthedocs.io/en/5.2.x/intro/tutorial01.html)

## 9. Parte 6 — Conectar as URLs ao projeto

Abra `config/urls.py` e substitua pelo código abaixo:

```python
# config/urls.py

from django.contrib import admin
from django.urls import include, path

urlpatterns = [
    path("admin/", admin.site.urls),
    path("paginas/", include("paginas.urls")),
]
```

O `include()` conecta o arquivo de URLs da aplicação ao URLconf principal do projeto. Assim, `/` carrega a Home, `/sobre/` carrega a página Sobre e `/politica-privacidade/` carrega a Política de Privacidade.

### 10.1. Blocos do template

| Bloco | Função |
| :--- | :--- |
| `{% block title %}` | Permite alterar o título em cada página. |
| `{% block content %}` | Área principal do conteúdo. |
| `{% block css %}` | Permite adicionar CSS específico em uma página. |
| `{% block js %}` | Permite adicionar JavaScript específico em uma página. |

A herança de templates evita repetir menu, rodapé e estrutura HTML em cada página. 

## 11. Parte 8 — Criar os templates das páginas

## ▶12. Parte 9 — Executar o projeto

```bash

```

| Página | URL |
| :--- | :--- |

O comando `migrate` cria as tabelas padrão do Django, incluindo as necessárias para autenticação, sessões e admin. [djangoproject](https://www.djangoproject.com/download/)

## 12. Parte 10 — Atividade prática

Cada aluno deve:

1. Criar uma nova página chamada **“Contato”**.
2. Criar a view `contato` em `paginas/views.py`.
3. Criar a URL `/contato/` com `name="contato"`.
4. Criar o template `paginas/templates/paginas/contato.html`.
5. Adicionar o link **Contato** no menu do `base.html`.
6. Testar o acesso pelo navegador.

## 13. Erros frequentes ⚠️

| Erro | Causa | Solução |
| :--- | :--- | :--- |
| `TemplateDoesNotExist: base.html` | `DIRS` não configurado | Use `BASE_DIR / "templates"` em `TEMPLATES`.  |
| `TemplateDoesNotExist: paginas/home.html` | Estrutura incorreta | Crie `paginas/templates/paginas/home.html`.  [docs.djangoproject](https://docs.djangoproject.com/en/6.1/intro/tutorial03/) |
| `NoReverseMatch` | `app_name` ausente | Adicione `app_name = "paginas"` em `paginas/urls.py`. |
| `ModuleNotFoundError` | App não registrada | Inclua `"paginas"` em `INSTALLED_APPS`.  [docs.djangoproject](https://docs.djangoproject.com/en/5.2/ref/django-admin/) |
| `Page not found (404)` | URL não incluída | Confirme `path("", include("paginas.urls"))` em `config/urls.py`.  [django.readthedocs](https://django.readthedocs.io/en/5.2.x/intro/tutorial01.html) |
| CSS não carrega | Sem internet ou CDN bloqueado | Verifique a conexão ou use Bootstrap local. |
