## 🎲 Formas de armazenamento de dados

A **escolha da estrutura de dados correta** é fundamental em Python, pois impacta diretamente na performance, na legibilidade e na eficiência do nosso código.

Em Python, existem diversas técnicas nativas (estruturas de dados internas ou *built-in types*) para **armazenamento e organização de dados** na memória. As principais são:

### :one: `list` (Lista)

  * **O que é:** É uma coleção ordenada e mutável (modificável) de itens. É a estrutura de dados mais versátil em Python.
  * **Características:**
      * **Ordenada:** Os itens possuem uma ordem definida (mantêm a ordem de inserção).
      * **Mutável:** Podemos adicionar, remover ou modificar elementos após a criação.
      * **Permite Duplicatas:** Pode conter o mesmo valor múltiplas vezes.
      * **Heterogênea:** Pode armazenar diferentes tipos de dados (números, strings, outras listas, etc.).
  * **Quando usar:**
      * Quando a ordem dos itens é importante.
      * Quando você precisa adicionar ou remover elementos dinamicamente.
      * Para implementar estruturas como pilhas (usando `append()` e `pop()`) ou filas.
  * **Exemplo:**



```python
# Criando uma lista de projetos
projetos = ["Sistema de Vendas", "API de Usuários", "Relatórios Financeiros"]

# Adicionando um novo projeto
projetos.append("Dashboard de Métricas") 
print(f"Lista após append: {projetos}")
# Saída: ['Sistema de Vendas', 'API de Usuários', 'Relatórios Financeiros', 'Dashboard de Métricas']

# Acessando um item (índice 0)
primeiro_projeto = projetos[0]
print(f"Primeiro projeto: {primeiro_projeto}")
# Saída: Sistema de Vendas
```

### :two: `tuple` (Tupla)

  * **O que é:** É uma coleção ordenada e **imutável** (não modificável) de itens.
  * **Características:**
      * **Ordenada:** Mantém a ordem de inserção.
      * **Imutável:** Uma vez criada, você não pode adicionar, remover ou alterar elementos. Se precisar de uma tupla diferente, deve criar uma nova.
      * **Permite Duplicatas:** Pode conter o mesmo valor.
      * **Heterogênea:** Pode armazenar diferentes tipos de dados.
  * **Quando usar:**
      * Quando você tem um conjunto de dados que **não deve mudar** (ex: coordenadas geográficas, constantes de configuração).
      * Para retornar múltiplos valores de uma função (é o que a função faz por padrão).
      * Quando você precisa de uma estrutura de dados que possa ser usada como chave em um dicionário (já que precisam ser imutáveis).
  * **Exemplo:**



```python
# Criando uma tupla com as credenciais de um banco de dados (que não devem mudar)
config_db = ("localhost", 5432, "usuario_dev") 

# Acessando o item (índice 1)
porta = config_db[1]
print(f"Porta do DB: {porta}")
# Saída: 5432

# Tentativa de alteração (resultaria em um erro/exception)
# config_db[0] = "novo_host" # Isso geraria um TypeError
```


### :three: `dict` (Dicionário)

  * **O que é:** É uma coleção **não-ordenada** (a partir do Python 3.7, mantêm a ordem de inserção, mas seu foco não é a ordem sequencial) de pares **chave: valor**.
  * **Características:**
      * **Chave-Valor:** Cada valor está associado a uma chave única, que é usada para acessá-lo.
      * **Mutável:** Podemos adicionar, remover ou modificar pares chave-valor.
      * **Chaves Únicas e Imutáveis:** As chaves devem ser únicas e precisam ser tipos imutáveis (como strings, números ou tuplas). Os valores podem ser qualquer coisa.
  * **Quando usar:**
      * Para representar dados estruturados, como um registro, um objeto ou um JSON.
      * Para pesquisas rápidas baseadas em uma chave.
      * Para contagem (como um *hash map*).
  * **Exemplo:**



```python
# Criando um dicionário para representar um desenvolvedor
desenvolvedor = {
    "nome": "Alice",
    "linguagem": "Python",
    "experiencia_anos": 5
}

# Acessando o valor pela chave
linguagem = desenvolvedor["linguagem"]
print(f"Linguagem principal: {linguagem}")
# Saída: Python

# Adicionando um novo par chave-valor
desenvolvedor["status"] = "Ativo"
print(f"Dicionário após adição: {desenvolvedor}")
# Saída: {'nome': 'Alice', 'linguagem': 'Python', 'experiencia_anos': 5, 'status': 'Ativo'}
```

### :four: `set` (Conjunto)

  * **O que é:** É uma coleção **não-ordenada** de itens **únicos**.
  * **Características:**
      * **Não-Ordenada:** A ordem dos itens não é garantida (embora possa parecer ordenada em algumas versões do Python, não se deve confiar nisso).
      * **Sem Duplicatas:** Automaticamente remove quaisquer valores duplicados.
      * **Mutável:** Você pode adicionar e remover itens.
      * **Itens Imutáveis:** Os itens armazenados no `set` devem ser tipos imutáveis (como strings, números ou tuplas).
  * **Quando usar:**
      * Para garantir que uma coleção contenha apenas valores únicos (remover duplicatas).
      * Para realizar operações matemáticas de conjuntos, como união, interseção e diferença.
      * Para testes de pertencimento muito rápidos (ex: `if item in meu_set:`).
  * **Exemplo:**



```python
# Criando um set de tecnologias (o 'Python' duplicado será ignorado)
tecnologias = {"Python", "Django", "JavaScript", "Python", "SQL"}

print(f"Set após criação: {tecnologias}")
# Saída: {'SQL', 'Python', 'Django', 'JavaScript'} (Ordem pode variar)

# Adicionando um novo elemento
tecnologias.add("Docker")

# Verificando se um item existe
existe_js = "JavaScript" in tecnologias
print(f"Existe JavaScript? {existe_js}")
# Saída: True
```

### 🐲 Resumo das Estruturas Principais:

|  Estrutura  | Símbolo |  Ordem Preservada?   | Mutável? (Alterável) | Permite Duplicatas? | Uso Comum                                                                       |
| :---------: | :-----: | :------------------: | :------------------: | :-----------------: | :------------------------------------------------------------------------------ |
| **`list`**  |  `[ ]`  |         Sim          |       **Sim**        |         Sim         | Coleção sequencial geral, pilhas, filas.                                        |
| **`tuple`** |  `( )`  |         Sim          |       **Não**        |         Sim         | Dados fixos, constantes, chaves de dicionário.                                  |
| **`dict`**  |  `{ }`  | Sim (pós Python 3.7) |       **Sim**        |  Não (nas chaves)   | Dados estruturados, registros, mapeamento chave-valor.                          |
|  **`set`**  |  `{ }`  |         Não          |       **Sim**        |       **Não**       | Remoção de duplicatas, operações de conjuntos, testes de pertencimento rápidos. |

🐉 **Dica**: Ao escolher qual usar, sempre pense: **Eu preciso da ordem? Os dados podem mudar? Eu preciso que sejam únicos?** A resposta a essas perguntas guiará você para a técnica de armazenamento mais eficiente\!


## 💾 Persistência de dados

O armazenamento em memória (como listas, tuplas e dicionários) é temporário e volátil. Para que nossos dados sobrevivam ao encerramento do programa e possam ser recuperados em uma execução futura, precisamos de técnicas de **persistência de dados**.

Em Python, existem diversas abordagens, desde a manipulação simples de **arquivos** até a utilização de **bancos de dados** robustos.

### :one: Persistência em Arquivos Simples (Texto/Binário)

Esta é a forma mais básica de persistência, utilizando as funções de manipulação de arquivos nativas do Python (`open()`, `read()`, `write()`).

#### :a: Arquivos de Texto Comum (`.txt`)

  * **O que é:** Armazenamento de dados como strings, formatados de maneira simples.
  * **Vantagens:** Extremamente simples de implementar e totalmente legível por humanos.
  * **Desvantagens:** É necessário escrever código customizado para "parsear" (analisar) as linhas e converter as strings de volta para tipos Python (como inteiros ou booleanos).
  * **Quando usar:** Para logs, arquivos de configuração simples ou dados que precisam ser facilmente lidos ou editados por um usuário.


 
🐍 **Exemplo**: Salvando um log simples

```python
dados = "10/05/2025: Processo iniciado\n10/05/2025: Tarefa concluída com sucesso"

with open("log.txt", "w") as arquivo:
    arquivo.write(dados)
# O arquivo log.txt é criado no disco.

# Exemplo: Recuperando o log
with open("log.txt", "r") as arquivo:
    conteudo = arquivo.read()
print(f"Conteúdo recuperado:\n{conteudo}")
```

#### :b: Arquivos CSV (Comma-Separated Values)

  * **O que é:** Um formato estruturado, onde os dados são organizados em linhas e colunas, com valores separados por um delimitador (geralmente vírgula).
  * **Módulo Python:** O módulo `csv` nativo facilita a leitura e escrita, tratando cada linha como uma lista ou dicionário.
  * **Vantagens:** Ideal para dados tabulares, compatível com planilhas (Excel, Google Sheets) e fácil de trocar com outros sistemas.
  * **Quando usar:** Quando você precisa armazenar dados que se assemelham a uma tabela, como listas de produtos, funcionários ou registros de transações.

### :two: Serialização de Objetos (JSON e Pickle)

**`Serialização`** é o processo de converter objetos Python complexos em um formato que possa ser armazenado (em um arquivo ou transmitido pela rede). **`Dessecação`** é o processo inverso.

#### :a: JSON (`.json`) - JavaScript Object Notation

  * **O que é:** Um formato de texto leve e muito popular para troca de dados. Em Python, é excelente para serializar estruturas como **dicionários** e **listas**.
  * **Módulo Python:** `json`.
  * **Vantagens:** **Interoperabilidade** (pode ser lido por quase todas as outras linguagens e sistemas), legível por humanos, e muito usado em APIs web.
  * **Desvantagens:** Não consegue serializar tipos complexos nativos do Python (como objetos de classes customizadas, funções ou `datetime`s) sem um trabalho extra.
  * **Quando usar:** Para salvar dados que precisam ser lidos por outros programas ou sistemas, ou para armazenar configurações da aplicação.


🐍 **Exemplo**:
```python
import json

# Dados em formato de dicionário Python
dados_app = {
    "versao": "1.0",
    "config_padrao": {"tema": "escuro", "idioma": "pt-br"},
    "lista_recursos": ["login", "relatorio", "cadastro"]
}

# Serialização (Escrita)
with open("config.json", "w") as arquivo:
    json.dump(dados_app, arquivo, indent=4) # O 'indent' melhora a legibilidade

# Desserialização (Leitura)
with open("config.json", "r") as arquivo:
    config_lida = json.load(arquivo)
print(f"Versão recuperada: {config_lida['versao']}")
```

#### :b: Pickle (`.pkl`) - Serialização Específica do Python

  * **O que é:** Um protocolo binário nativo do Python usado para serializar (ou "pickle") uma estrutura de objeto completa.
  * **Módulo Python:** `pickle`.
  * **Vantagens:** Pode serializar **quase todos os objetos Python**, incluindo instâncias de classes, funções e tipos de dados complexos, preservando seu estado exato.
  * **Desvantagens:** O formato é **específico do Python** (não legível por humanos ou outras linguagens) e é **inseguro** (desempacotar/unpickling dados de uma fonte não confiável pode executar código malicioso).
  * **Quando usar:** Para salvar o estado de objetos Python complexos (como um modelo de Machine Learning treinado ou o estado de uma sessão de usuário) para ser recuperado e usado apenas pelo próprio Python.

🐍 **Exemplo**:

```python
import pickle

class Tarefa:
    def __init__(self, nome, completa=False):
        self.nome = nome
        self.completa = completa

tarefa_unica = Tarefa("Ajustar o código de persistência", completa=True)

# Serialização (Escrita)
with open("tarefa.pkl", "wb") as arquivo: # 'wb' = write binary
    pickle.dump(tarefa_unica, arquivo)

# Desserialização (Leitura)
with open("tarefa.pkl", "rb") as arquivo: # 'rb' = read binary
    tarefa_recuperada = pickle.load(arquivo)

print(f"Tarefa: {tarefa_recuperada.nome}, Completa: {tarefa_recuperada.completa}")
```


### :three: Bancos de Dados (SQLite)

Quando a aplicação cresce e a necessidade de pesquisa, atualização e gerenciamento de grandes volumes de dados se torna crucial, bancos de dados são a solução ideal.

#### 🦖 SQLite (`.db`)

  * **O que é:** Um sistema de gerenciamento de banco de dados relacional (RDBMS) que é **integrado no Python** (não requer um servidor separado). O banco de dados inteiro é armazenado em um único arquivo de disco.
  * **Módulo Python:** `sqlite3`.
  * **Vantagens:** Zero-configuração (não precisa de instalação ou servidor), ideal para aplicações *desktop* ou pequenos projetos onde um banco de dados completo seria exagerado. Permite consultas SQL complexas.
  * **Desvantagens:** Não é adequado para aplicações com muitos acessos concorrentes (muitos usuários acessando ao mesmo tempo), como grandes aplicações web.
  * **Quando usar:** Protótipos, desenvolvimento local, pequenas aplicações que precisam de estrutura de dados relacional e capacidade de consulta.


🐍 **Exemplo**:

```python
import sqlite3

# Conecta ou cria o arquivo do banco de dados
conexao = sqlite3.connect("dados_dev.db")
cursor = conexao.cursor()

# 1. Cria a tabela (se não existir)
cursor.execute("""
CREATE TABLE IF NOT EXISTS desenvolvedores (
    id INTEGER PRIMARY KEY,
    nome TEXT,
    linguagem TEXT
)
""")

# 2. Insere dados
cursor.execute("INSERT INTO desenvolvedores (nome, linguagem) VALUES (?, ?)", ("Carlos", "Python"))
conexao.commit() # Salva as alterações no disco

# 3. Consulta dados
cursor.execute("SELECT nome, linguagem FROM desenvolvedores WHERE linguagem='Python'")
registros = cursor.fetchall()

print(f"Registros encontrados: {registros}")
# Saída: [('Carlos', 'Python')]

conexao.close()
```

### 🐲 Resumo sobre Persistência de dados

|  Técnica   |    Formato    |          Ideal para           |            Vantagens             |                  Desvantagens                   |
| :--------: | :-----------: | :---------------------------: | :------------------------------: | :---------------------------------------------: |
|  **JSON**  |     Texto     | Troca de dados, Configurações |      Interoperável, legível      |      Não lida bem com classes customizadas      |
| **Pickle** |    Binário    |   Objetos Python complexos    | Serializa *quase* tudo em Python |   Específico do Python, potencial insegurança   |
| **SQLite** | Arquivo `.db` | Dados estruturados/tabelares  |    Zero-config, consultas SQL    |           Limitações em concorrência            |
|  **CSV**   |     Texto     |    Dados tabulares simples    |     Compatível com planilhas     | Lida apenas com tipos básicos e é menos robusto |
