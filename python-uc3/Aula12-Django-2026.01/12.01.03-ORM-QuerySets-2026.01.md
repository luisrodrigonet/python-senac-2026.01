# Aula 12 — Django ORM: QuerySets 🛰️

O **ORM** (*Object-Relational Mapper*) do Django permite trabalhar com o banco de dados por meio de classes e objetos Python. Em vez de escrever SQL manualmente, você usa o `Model.objects` para criar, consultar, atualizar e remover registros; o Django traduz essas operações em SQL. 

Nesta aula, usaremos os modelos `Categoria` e `Receita` abaixo. Eles representam receitas culinárias, com autor, categorias, tempo de preparo e status de publicação.

```python
from django.contrib.auth.models import User
from django.db import models


class Categoria(models.Model):
    """Representa uma categoria de receita, como Sobremesa ou Jantar."""

    nome = models.CharField(max_length=100)

    class Meta:
        verbose_name = "Categoria"
        verbose_name_plural = "Categorias"
        ordering = ["nome"]

    def __str__(self):
        return self.nome


class Receita(models.Model):
    """Representa uma receita publicada no sistema."""

    titulo = models.CharField(max_length=200)
    ingredientes = models.TextField(
        help_text="Informe um ingrediente por linha."
    )
    modo_preparo = models.TextField(
        help_text="Descreva o passo a passo do preparo."
    )
    tempo_preparo = models.PositiveIntegerField(
        help_text="Tempo total de preparo, em minutos."
    )
    data_publicacao = models.DateTimeField(auto_now_add=True)
    publicada = models.BooleanField(default=False)

    # Relação N:N: uma receita pode ter várias categorias
    # e uma categoria pode estar em várias receitas.
    categorias = models.ManyToManyField(
        Categoria,
        related_name="receitas",
        blank=True,
    )

    # Relação 1:N: cada receita pertence a um autor.
    autor = models.ForeignKey(
        User,
        on_delete=models.CASCADE,
        related_name="receitas",
    )

    class Meta:
        verbose_name = "Receita"
        verbose_name_plural = "Receitas"
        ordering = ["-data_publicacao"]

    def __str__(self):
        return self.titulo
```

## 1. O que é um QuerySet?

Um **`QuerySet`** é uma coleção “preguiçosa” de objetos do banco de dados. Ele descreve uma consulta, mas normalmente **não executa SQL no momento em que é criado**. 

```python
# Nenhuma consulta SQL é executada aqui.
receitas = Receita.objects.filter(publicada=True)

# Agora o Django executa a consulta para obter os registros.
for receita in receitas:
    print(receita.titulo)
```

Esse comportamento é chamado de **lazy evaluation**, ou *avaliação preguiçosa*: a consulta é adiada até que os dados sejam realmente necessários. 

### 1.1. Quando a consulta é executada?

O `QuerySet` é avaliado — e o SQL é enviado ao banco — quando você:

- **Itera** com `for receita in receitas:`
- **Converte** para lista: `list(receitas)`
- **Acessa** um índice: `receitas[0]`
- **Fatia** com limite: `receitas[:10]`
- **Chama** `count()`, `exists()`, `first()`, `last()` ou `get()`
- **Usa** o `QuerySet` em um template Django
- **Serializa** os dados, por exemplo, em uma API

```python
# Ainda não executou SQL.
receitas = Receita.objects.filter(publicada=True)

# Executa SQL para verificar existência.
if receitas.exists():
    print("Existem receitas publicadas.")

# Executa SQL para contar registros.
total = receitas.count()

# Executa SQL para obter os objetos.
for receita in receitas:
    print(receita.titulo)
```

### 1.2. Cache do QuerySet

Depois que um `QuerySet` é avaliado, o Django normalmente **armazena em cache** os resultados obtidos. Assim, iterar novamente sobre o **mesmo objeto `QuerySet`** não gera uma nova consulta. 

```python
receitas = Receita.objects.filter(publicada=True)

# Primeira avaliação: executa a consulta.
for receita in receitas:
    print(receita.titulo)

# Segunda avaliação do MESMO QuerySet: usa o cache.
for receita in receitas:
    print(receita.titulo)
```

> ⚠️ **Atenção:** 
> 
> - Criar um novo `QuerySet` gera uma nova consulta quando ele for avaliado.
>
>  ```python
>  # Estes são QuerySets diferentes.
>  Receita.objects.filter(publicada=True)
>  Receita.objects.filter(publicada=True)
>  ```
>  ---

## 2. Métodos que retornam QuerySets

Os métodos abaixo retornam **novos `QuerySets`**. Isso permite encadeá-los, pois cada método refina a consulta anterior.

```python
Receita.objects.filter(publicada=True).order_by("titulo")
```

### 2.1. `all()`

Retorna todos os registros do modelo, respeitando o `ordering` definido no `Meta`.

```python
# Retorna todas as receitas.
receitas = Receita.objects.all()

# Como o Meta define ordering = ["-data_publicacao"],
# as receitas vêm das mais recentes para as mais antigas.
for receita in receitas:
    print(receita.titulo)
```

| Item | Explicação |
|---|---|
| `Receita.objects` | Manager padrão do modelo; é a porta de entrada para consultas. |
| `.all()` | Retorna um `QuerySet` com todos os registros. |
| `ordering` | Define a ordenação padrão das consultas. |

### 2.2. `filter()`

Retorna apenas os objetos que atendem às condições informadas. Vários argumentos em um mesmo `filter()` são combinados com **AND**. 

```python
# Receitas publicadas.
receitas_publicadas = Receita.objects.filter(publicada=True)

# Receitas com até 30 minutos de preparo.
receitas_rapidas = Receita.objects.filter(tempo_preparo__lte=30)

# Receitas publicadas e rápidas: as duas condições são obrigatórias.
receitas = Receita.objects.filter(
    publicada=True,
    tempo_preparo__lte=30,
)
```

#### 2.2.1 Lookups de campo

Os **lookups** são sufixos separados por `__` que definem como o Django compara os valores.

```python
Receita.objects.filter(campo__lookup=valor)
```

| Lookup | Significado | Exemplo |
|---|---|---|
| `exact` | Igualdade exata; é o padrão quando nenhum lookup é informado | `filter(titulo__exact="Bolo de chocolate")` |
| `iexact` | Igualdade sem diferenciar maiúsculas de minúsculas | `filter(titulo__iexact="bolo de chocolate")` |
| `contains` | Contém o texto, diferenciando maiúsculas e minúsculas | `filter(titulo__contains="chocolate")` |
| `icontains` | Contém o texto, ignorando maiúsculas e minúsculas | `filter(titulo__icontains="chocolate")` |
| `startswith` | Começa com o texto informado | `filter(titulo__startswith="Bolo")` |
| `istartswith` | Começa com o texto, sem diferenciar maiúsculas | `filter(titulo__istartswith="bolo")` |
| `endswith` | Termina com o texto informado | `filter(titulo__endswith="chocolate")` |
| `iendswith` | Termina com o texto, sem diferenciar maiúsculas | `filter(titulo__iendswith="chocolate")` |
| `gt` | Maior que (*greater than*) | `filter(tempo_preparo__gt=30)` |
| `gte` | Maior ou igual a (*greater than or equal to*) | `filter(tempo_preparo__gte=30)` |
| `lt` | Menor que (*less than*) | `filter(tempo_preparo__lt=30)` |
| `lte` | Menor ou igual a (*less than or equal to*) | `filter(tempo_preparo__lte=30)` |
| `in` | Valor presente em uma lista, tupla ou outro QuerySet | `filter(tempo_preparo__in=[15, 30, 45])` |
| `range` | Entre dois valores, incluindo os extremos | `filter(tempo_preparo__range=(15, 45))` |
| `isnull` | Verifica se o valor é `NULL` | `filter(categorias__isnull=True)` |
| `date` | Extrai ou compara a parte de data de um `DateTimeField` | `filter(data_publicacao__date__gte="2026-01-01")` |
| `year`, `month`, `day` | Compara partes da data | `filter(data_publicacao__year=2026)` |

```python
# Busca receitas cujo título contenha "bolo", ignorando maiúsculas/minúsculas.
receitas = Receita.objects.filter(titulo__icontains="bolo")

# Receitas com tempo de preparo entre 15 e 45 minutos.
receitas = Receita.objects.filter(tempo_preparo__range=(15, 45))

# Receitas publicadas em 2026.
receitas = Receita.objects.filter(data_publicacao__year=2026)

# Receitas cujo título está entre os valores informados.
receitas = Receita.objects.filter(
    titulo__in=["Bolo de cenoura", "Lasanha", "Pudim"]
)
```

### 2.3. Filtrando relacionamentos

Você pode atravessar relacionamentos usando `__`.

```python
# Receitas da categoria "Sobremesa".
receitas = Receita.objects.filter(categorias__nome="Sobremesa")

# Receitas do usuário com username "maria".
receitas = Receita.objects.filter(autor__username="maria")

# Receitas de categorias cujo nome contém "doce".
receitas = Receita.objects.filter(categorias__nome__icontains="doce")
```

| Relacionamento | Como acessar no filtro | Exemplo |
|---|---|---|
| `ForeignKey` direto | Nome do campo | `autor__username` |
| `ManyToManyField` direto | Nome do campo | `categorias__nome` |
| Relação reversa | `related_name` | `receitas__titulo` |

Como `Categoria` possui `related_name="receitas"`, é possível filtrar categorias a partir das receitas:

```python
# Categorias que possuem receitas publicadas.
categorias = Categoria.objects.filter(receitas__publicada=True).distinct()
```

### 2.4. `exclude()`

Retorna os objetos que **não atendem** às condições informadas.

```python
# Receitas não publicadas.
receitas = Receita.objects.exclude(publicada=True)

# Receitas que não são rápidas.
receitas = Receita.objects.exclude(tempo_preparo__lte=30)

# Receitas que não são da categoria "Sobremesa".
receitas = Receita.objects.exclude(categorias__nome="Sobremesa")
```

> ⚠️ **Cuidado:** 
> 
> - `exclude()` com relacionamentos pode gerar resultados diferentes do esperado quando há múltiplas correspondências. 
> - Por exemplo, excluir receitas com `categorias__nome="Sobremesa"` remove qualquer receita que tenha **ao menos uma** categoria chamada “Sobremesa”.
>
> ```python
> # Remove receitas que possuem a categoria "Sobremesa".
> Receita.objects.exclude(categorias__nome="Sobremesa")
> ```
> ---



### 2.5. `order_by()`

Define a ordem dos resultados. Um hífen antes do nome do campo indica ordem **decrescente**.

```python
# Da receita mais antiga para a mais recente.
receitas = Receita.objects.order_by("data_publicacao")

# Da mais recente para a mais antiga.
receitas = Receita.objects.order_by("-data_publicacao")

# Ordena por título e, em caso de empate, pelo menor tempo de preparo.
receitas = Receita.objects.order_by("titulo", "tempo_preparo")

# Ordena pelo nome do autor.
receitas = Receita.objects.order_by("autor__username")

# Ordenação aleatória.
receitas = Receita.objects.order_by("?")
```

| Argumento | Efeito |
|---|---|
| `"campo"` | Ordem crescente |
| `"-campo"` | Ordem decrescente |
| `"campo1", "campo2"` | Ordena pelo primeiro campo; usa o segundo como desempate |
| `"?"` | Ordem aleatória |

O `ordering` do `Meta` é aplicado por padrão, mas `order_by()` **substitui** essa ordenação na consulta atual.

```python
# O Meta ordena por -data_publicacao.
# Aqui, a ordenação passa a ser por título.
receitas = Receita.objects.order_by("titulo")
```

### 2.6. `distinct()`

Remove registros duplicados do resultado. Ele é especialmente útil após filtros em relacionamentos, pois uma receita pode aparecer mais de uma vez quando possui várias categorias compatíveis com o filtro.

```python
# Categorias que possuem receitas publicadas.
# distinct() evita que a mesma categoria apareça várias vezes.
categorias = Categoria.objects.filter(
    receitas__publicada=True
).distinct()
```

```python
# Autores que publicaram receitas rápidas.
autores = User.objects.filter(
    receitas__publicada=True,
    receitas__tempo_preparo__lte=30,
).distinct()
```

### 2.7. `select_related()`

O `select_related()` otimiza o acesso a relacionamentos **`ForeignKey`** e **`OneToOneField`**. Ele usa um `JOIN` SQL para trazer o objeto principal e o relacionado na **mesma consulta**. 

No nosso modelo, `autor` é uma `ForeignKey`; portanto, `select_related("autor")` é adequado.

```python
# Sem otimização:
# 1 consulta para as receitas + 1 consulta para cada autor acessado.
receitas = Receita.objects.all()

for receita in receitas:
    print(receita.titulo, receita.autor.username)


# Com otimização:
# 1 consulta única, com JOIN entre Receita e User.
receitas = Receita.objects.select_related("autor")

for receita in receitas:
    print(receita.titulo, receita.autor.username)
```

```python
# Também é possível filtrar e ordenar normalmente.
receitas = Receita.objects.filter(
    publicada=True
).select_related("autor").order_by("-data_publicacao")
```

⚠️ No Django 6.1, chamar `select_related()` **sem argumentos** está deprecado. Informe explicitamente os relacionamentos que deseja carregar. 

```python
# ❌ Evite no Django 6.1.
Receita.objects.select_related()

# ✅ Preferível.
Receita.objects.select_related("autor")
```

### 2.8. `prefetch_related()`

O `prefetch_related()` otimiza relacionamentos **`ManyToManyField`** e relacionamentos reversos. Ele executa uma consulta adicional para buscar os objetos relacionados e faz a associação em Python. 

No nosso modelo:

- `categorias` é um `ManyToManyField`;
- `receitas`, em `Categoria`, é o relacionamento reverso de `ForeignKey`.

```python
# Sem otimização:
# 1 consulta para as receitas + 1 consulta para cada receita.
receitas = Receita.objects.all()

for receita in receitas:
    print(receita.titulo, receita.categorias.all())


# Com prefetch_related():
# 1 consulta para as receitas + 1 consulta para todas as categorias.
receitas = Receita.objects.prefetch_related("categorias")

for receita in receitas:
    print(receita.titulo, receita.categorias.all())
```

```python
# Prefetch do relacionamento reverso:
# cada categoria carrega suas receitas em lote.
categorias = Categoria.objects.prefetch_related("receitas")

for categoria in categorias:
    print(categoria.nome, categoria.receitas.all())
```

### 2.9. `Prefetch()`

Use `Prefetch()` quando precisar controlar o `QuerySet` usado no prefetch, por exemplo, para filtrar ou ordenar os itens relacionados.

```python
from django.db.models import Prefetch

receitas_publicadas = Receita.objects.filter(publicada=True)

categorias = Categoria.objects.prefetch_related(
    Prefetch(
        "receitas",
        queryset=receitas_publicadas.order_by("-data_publicacao"),
    )
)

for categoria in categorias:
    print(categoria.nome)

    for receita in categoria.receitas.all():
        print(f"- {receita.titulo}")
```

| Método | Relação indicada | Estratégia SQL | Exemplo no projeto |
|---|---|---|---|
| `select_related()` | `ForeignKey`, `OneToOneField` | `JOIN` em uma única consulta | `select_related("autor")` |
| `prefetch_related()` | `ManyToManyField`, relação reversa | Consulta adicional e junção em Python | `prefetch_related("categorias")` |

## 2.10 Consultas complexas com `Q`

Por padrão, vários argumentos passados a `filter()` são combinados com **AND**. Para usar **OR**, **NOT** ou agrupar condições, utilize objetos `Q`.

```python
from django.db.models import Q
```

| Operador | Significado | Exemplo |
|---|---|---|
| `&` | **AND**: ambas as condições devem ser verdadeiras | `Q(publicada=True) & Q(tempo_preparo__lte=30)` |
| `\|` | **OR**: pelo menos uma condição deve ser verdadeira | `Q(titulo__icontains="bolo") \| Q(titulo__icontains="pizza")` |
| `~` | **NOT**: nega a condição | `~Q(publicada=True)` |

### 2.10.1  `OR`

```python
from django.db.models import Q

# Receitas com "bolo" OU "pizza" no título.
receitas = Receita.objects.filter(
    Q(titulo__icontains="bolo") | Q(titulo__icontains="pizza")
)
```

### 2.10.2 `AND`

```python
from django.db.models import Q

# Receitas publicadas E com até 30 minutos.
receitas = Receita.objects.filter(
    Q(publicada=True) & Q(tempo_preparo__lte=30)
)
```

Também é possível usar argumentos comuns junto de `Q`. Argumentos fora de `Q` são combinados com **AND**.

```python
from django.db.models import Q

receitas = Receita.objects.filter(
    Q(titulo__icontains="bolo") | Q(titulo__icontains="pizza"),
    publicada=True,
    tempo_preparo__lte=45,
)
```

### 2.10.3 `NOT`

```python
from django.db.models import Q

# Receitas que não estão publicadas.
receitas = Receita.objects.filter(~Q(publicada=True))

# Receitas publicadas que não são sobremesas.
receitas = Receita.objects.filter(
    Q(publicada=True) & ~Q(categorias__nome="Sobremesa")
)
```

### 2.10.4  Agrupamento lógico

Use parênteses para controlar a precedência das condições.

```python
from django.db.models import Q

receitas = Receita.objects.filter(
    (
        Q(titulo__icontains="bolo")
        | Q(titulo__icontains="pizza")
    )
    & Q(publicada=True)
    & Q(tempo_preparo__lte=45)
)
```

A consulta acima significa:

> **(título contém “bolo” OU título contém “pizza”) E está publicada E leva no máximo 45 minutos.**

### 2.10.5 Consultas dinâmicas

`Q` é muito útil quando os filtros dependem de dados enviados pelo usuário.

```python
from django.db.models import Q

from .models import Receita


def buscar_receitas(
    termo=None,
    tempo_maximo=None,
    apenas_publicadas=True,
):
    """Busca receitas aplicando apenas os filtros recebidos."""

    filtros = Q()

    if termo:
        # Busca no título OU nos ingredientes.
        filtros &= (
            Q(titulo__icontains=termo)
            | Q(ingredientes__icontains=termo)
        )

    if tempo_maximo:
        filtros &= Q(tempo_preparo__lte=tempo_maximo)

    if apenas_publicadas:
        filtros &= Q(publicada=True)

    return Receita.objects.filter(filtros).order_by("-data_publicacao")
```

```python
# Busca apenas receitas publicadas.
receitas = buscar_receitas()

# Busca receitas com "chocolate" e até 60 minutos.
receitas = buscar_receitas(termo="chocolate", tempo_maximo=60)

# Busca qualquer receita, inclusive não publicada.
receitas = buscar_receitas(termo="chocolate", apenas_publicadas=False)
```

## 2.11. Agregações: `annotate()` e `aggregate()`

Agregações calculam valores como contagem, soma, média, mínimo e máximo **no banco de dados**, em vez de carregar todos os registros e calcular em Python.

```python
from django.db.models import Avg, Count, Max, Min, Sum
```

| Função | Finalidade |
|---|---|
| `Count` | Conta registros |
| `Sum` | Soma valores numéricos |
| `Avg` | Calcula média |
| `Min` | Retorna o menor valor |
| `Max` | Retorna o maior valor |

### 2.11.1  `annotate()`

`annotate()` adiciona um **campo calculado a cada objeto** do `QuerySet`. Ele é ideal para relações “por item”, como contar quantas receitas cada categoria possui. [docs.djangoproject](https://docs.djangoproject.com/en/dev//ref/models/querysets/)

```python
from django.db.models import Count

# Cada categoria recebe o atributo total_receitas.
categorias = Categoria.objects.annotate(
    total_receitas=Count("receitas")
)

for categoria in categorias:
    print(categoria.nome, categoria.total_receitas)
```

```python
from django.db.models import Avg, Count

# Cada autor recebe a quantidade de receitas e o tempo médio de preparo.
autores = User.objects.annotate(
    total_receitas=Count("receitas"),
    tempo_medio=Avg("receitas__tempo_preparo"),
).order_by("-total_receitas")

for autor in autores:
    print(
        autor.username,
        autor.total_receitas,
        autor.tempo_medio,
    )
```

É possível filtrar com base em uma anotação:

```python
from django.db.models import Count

# Categorias com mais de 5 receitas.
categorias = Categoria.objects.annotate(
    total_receitas=Count("receitas")
).filter(total_receitas__gt=5)
```

⚠️ **Cuidado:** quando você filtra usando uma anotação, o filtro é aplicado **após** o cálculo da agregação.

### 2.11.2 `aggregate()`

`aggregate()` calcula valores para o **conjunto inteiro** do `QuerySet` e retorna um dicionário, não objetos do modelo.

```python
from django.db.models import Avg, Count, Max, Min

estatisticas = Receita.objects.aggregate(
    total_receitas=Count("id"),
    tempo_medio=Avg("tempo_preparo"),
    tempo_minimo=Min("tempo_preparo"),
    tempo_maximo=Max("tempo_preparo"),
)

print(estatisticas)
# Exemplo:
# {
#     'total_receitas': 42,
#     'tempo_medio': 38.5,
#     'tempo_minimo': 10,
#     'tempo_maximo': 120,
# }
```

```python
from django.db.models import Avg

# Estatísticas apenas das receitas publicadas.
estatisticas = Receita.objects.filter(
    publicada=True
).aggregate(
    total=Count("id"),
    tempo_medio=Avg("tempo_preparo"),
)

print(estatisticas["total"])
print(estatisticas["tempo_medio"])
```

Se você não atribuir um nome ao resultado, o Django cria uma chave automática:

```python
from django.db.models import Avg

resultado = Receita.objects.aggregate(Avg("tempo_preparo"))

print(resultado)
# {'tempo_preparo__avg': 38.5}
```

### 2.11.3 Diferença entre `annotate()` e `aggregate()`

| Método | Resultado | Uso típico |
|---|---|---|
| `annotate()` | Um valor calculado **para cada objeto** | “Quantas receitas cada categoria possui?” |
| `aggregate()` | Um valor calculado **para todo o QuerySet** | “Qual é o tempo médio de todas as receitas?” |

```python
# annotate(): uma contagem por categoria.
Categoria.objects.annotate(total_receitas=Count("receitas"))

# aggregate(): uma contagem total.
Receita.objects.aggregate(total=Count("id"))
```

## 2.12. Métodos que retornam valores

Estes métodos executam a consulta e retornam um objeto, um booleano, um número ou dados simplificados.

### 2.12.1  `get()`

Retorna **exatamente um objeto**. Levanta `DoesNotExist` se não houver resultado e `MultipleObjectsReturned` se houver mais de um. 

```python
try:
    receita = Receita.objects.get(pk=1)
    print(receita.titulo)

except Receita.DoesNotExist:
    print("Nenhuma receita encontrada com esse ID.")

except Receita.MultipleObjectsReturned:
    print("Mais de uma receita corresponde ao filtro.")
```

```python
# Busca uma receita pelo título.
receita = Receita.objects.get(titulo="Bolo de cenoura")
```

⚠️ Use `get()` somente quando tiver certeza de que existe **um único** registro correspondente. Caso contrário, prefira `filter()` com `first()`.

### 2.12.2 `first()` e `last()`

Retornam o primeiro ou o último objeto do `QuerySet`. Se não houver registros, retornam `None`.

```python
# Primeira receita publicada, considerando a ordenação padrão.
primeira = Receita.objects.filter(publicada=True).first()

# Última receita publicada, considerando a ordenação padrão.
ultima = Receita.objects.filter(publicada=True).last()

# Receita mais rápida.
mais_rapida = Receita.objects.order_by("tempo_preparo").first()

# Receita mais demorada.
mais_demorada = Receita.objects.order_by("tempo_preparo").last()
```

```python
receita = Receita.objects.filter(publicada=True).first()

if receita:
    print(receita.titulo)
else:
    print("Nenhuma receita publicada.")
```

### 2.12.3 `count()`

Retorna a quantidade de registros do `QuerySet`.

```python
total = Receita.objects.count()
publicadas = Receita.objects.filter(publicada=True).count()

print(f"Total: {total}")
print(f"Publicadas: {publicadas}")
```

### 2.12.3 `exists()`

Retorna `True` se houver pelo menos um registro; caso contrário, retorna `False`.

```python
if Receita.objects.filter(titulo__icontains="bolo").exists():
    print("Já existe uma receita com 'bolo' no título.")
```

Prefira `exists()` em vez de `count()` quando você só precisa saber **se algo existe**.

```python
# ✅ Melhor para verificar existência.
if Receita.objects.filter(titulo="Bolo de cenoura").exists():
    ...

# ❌ Funciona, mas é desnecessário para uma verificação simples.
if Receita.objects.filter(titulo="Bolo de cenoura").count() > 0:
    ...
```

### 2.12.4 `values()`

Retorna dicionários, em vez de instâncias do modelo. É útil quando você precisa apenas de campos específicos.

```python
dados = Receita.objects.filter(publicada=True).values(
    "id",
    "titulo",
    "tempo_preparo",
)

for item in dados:
    print(item["titulo"], item["tempo_preparo"])
```

```python
# Exemplo de retorno:
# [
#     {'id': 1, 'titulo': 'Bolo de cenoura', 'tempo_preparo': 45},
#     {'id': 2, 'titulo': 'Lasanha', 'tempo_preparo': 60},
# ]
```

### 2.12.5 `values_list()`

Retorna tuplas em vez de dicionários.

```python
dados = Receita.objects.filter(publicada=True).values_list(
    "titulo",
    "tempo_preparo",
)

for titulo, tempo in dados:
    print(titulo, tempo)
```

```python
# Retorna apenas uma lista de títulos.
titulos = Receita.objects.filter(
    publicada=True
).values_list("titulo", flat=True)

print(list(titulos))
# ['Bolo de cenoura', 'Lasanha', 'Pudim']
```

| Método | Retorno | Quando usar |
|---|---|---|
| `values()` | Lista de dicionários | Quando precisa acessar valores por nome de campo |
| `values_list()` | Lista de tuplas | Quando precisa apenas dos valores |
| `values_list(..., flat=True)` | Lista simples | Quando seleciona apenas um campo |

## 2.13 Criação e atualização

### `create()`

Cria e salva um objeto em uma única operação.

```python
from django.contrib.auth.models import User

autor = User.objects.get(username="maria")

receita = Receita.objects.create(
    titulo="Bolo de cenoura",
    ingredientes="3 cenouras\n4 ovos\n2 xícaras de açúcar",
    modo_preparo="Bata os ingredientes e asse por 40 minutos.",
    tempo_preparo=45,
    publicada=True,
    autor=autor,
)

print(receita.id)
```

### `get_or_create()`

Busca um objeto; se ele não existir, cria um novo. Retorna uma tupla com o objeto e um booleano indicando se ele foi criado.

```python
categoria, criada = Categoria.objects.get_or_create(
    nome="Sobremesa"
)

if criada:
    print("Categoria criada.")
else:
    print("Categoria já existia.")
```

Use `defaults` para informar valores que devem ser aplicados apenas na criação.

```python
from django.contrib.auth.models import User

autor = User.objects.get(username="maria")

receita, criada = Receita.objects.get_or_create(
    titulo="Bolo de cenoura",
    autor=autor,
    defaults={
        "ingredientes": "3 cenouras\n4 ovos\n2 xícaras de açúcar",
        "modo_preparo": "Bata os ingredientes e asse por 40 minutos.",
        "tempo_preparo": 45,
        "publicada": True,
    },
)

if criada:
    print("Receita criada.")
else:
    print("Receita já existia.")
```

⚠️ Os argumentos fora de `defaults` são usados tanto para **buscar** quanto para **criar**. Os valores dentro de `defaults` são usados apenas na criação.

### `update_or_create()`

Busca um objeto e o atualiza; se ele não existir, cria um novo.

```python
categoria, criada = Categoria.objects.update_or_create(
    nome="Sobremesa",
    defaults={
        "nome": "Sobremesas",
    },
)

if criada:
    print("Categoria criada.")
else:
    print("Categoria atualizada.")
```

```python
from django.contrib.auth.models import User

autor = User.objects.get(username="maria")

receita, criada = Receita.objects.update_or_create(
    titulo="Bolo de cenoura",
    autor=autor,
    defaults={
        "tempo_preparo": 50,
        "publicada": True,
    },
)
```

### `update()`

Atualiza diretamente todos os registros que correspondem ao filtro, sem carregar cada objeto em Python.

```python
# Publica todas as receitas rápidas.
Receita.objects.filter(
    tempo_preparo__lte=30
).update(publicada=True)
```

```python
# Define todas as receitas de uma categoria como não publicadas.
Receita.objects.filter(
    categorias__nome="Sobremesa"
).update(publicada=False)
```

Use `F()` para atualizar um campo com base no próprio valor atual.

```python
from django.db.models import F

# Aumenta o tempo de preparo em 5 minutos.
Receita.objects.filter(
    tempo_preparo__gt=0
).update(
    tempo_preparo=F("tempo_preparo") + 5
)
```

`F()` referencia o valor atual do campo no banco, evitando condições de corrida quando vários processos atualizam o mesmo registro.

### `bulk_create()`

Cria vários objetos em lote, com melhor desempenho do que chamar `create()` repetidamente.

```python
from django.contrib.auth.models import User

autor = User.objects.get(username="maria")

receitas = [
    Receita(
        titulo="Bolo de chocolate",
        ingredientes="Chocolate\nFarinha\nOvos",
        modo_preparo="Misture e asse.",
        tempo_preparo=50,
        publicada=True,
        autor=autor,
    ),
    Receita(
        titulo="Panqueca",
        ingredientes="Farinha\nLeite\nOvos",
        modo_preparo="Misture e frite.",
        tempo_preparo=20,
        publicada=True,
        autor=autor,
    ),
]

Receita.objects.bulk_create(receitas)
```

⚠️ `bulk_create()` é rápido, mas normalmente **não chama `save()` individualmente**, não dispara signals `pre_save`/`post_save` para cada objeto e pode não preencher a `pk` em todos os bancos de dados.

### `delete()`

Remove registros do banco de dados.

```python
# Remove uma receita específica.
receita = Receita.objects.get(pk=1)
receita.delete()

# Remove várias receitas não publicadas.
Receita.objects.filter(publicada=False).delete()

# Remove todas as receitas.
Receita.objects.all().delete()
```

🚨 **Atenção:** `delete()` é irreversível. Como `autor` usa `on_delete=models.CASCADE`, excluir um `User` também exclui as receitas associadas a ele.

```python
# Exemplo perigoso:
# remove o usuário e, por cascata, todas as receitas dele.
autor = User.objects.get(username="maria")
autor.delete()
```

## Exemplo prático: página de receitas

```python
from django.db.models import Count, Prefetch, Q

from .models import Categoria, Receita


def listar_receitas(termo=None, categoria=None):
    """Lista receitas publicadas com filtros opcionais."""

    receitas = (
        Receita.objects
        .filter(publicada=True)
        .select_related("autor")
        .prefetch_related("categorias")
        .order_by("-data_publicacao")
    )

    if termo:
        receitas = receitas.filter(
            Q(titulo__icontains=termo)
            | Q(ingredientes__icontains=termo)
        )

    if categoria:
        receitas = receitas.filter(
            categorias__nome__iexact=categoria
        ).distinct()

    return receitas
```

```python
# Lista todas as receitas publicadas.
receitas = listar_receitas()

# Busca receitas com "chocolate".
receitas = listar_receitas(termo="chocolate")

# Lista receitas da categoria "Sobremesa".
receitas = listar_receitas(categoria="Sobremesa")
```

## Boas práticas 🚀

- Use `filter()` em vez de `get()` quando o resultado pode ser zero ou mais de um registro.
- Use `exists()` para verificar existência e `count()` para obter quantidades.
- Use `select_related("autor")` ao exibir o autor de várias receitas.
- Use `prefetch_related("categorias")` ao exibir as categorias de várias receitas.
- Use `Prefetch()` quando precisar filtrar ou ordenar os itens relacionados.
- Use `Q` para condições com `OR`, `NOT` e agrupamentos lógicos.
- Use `annotate()` para métricas por objeto e `aggregate()` para métricas globais.
- Use `update()` para alterações em lote e `bulk_create()` para inserções em lote.
- Nunca use `delete()` em massa sem confirmar o filtro; uma condição incorreta pode remover muitos registros.
