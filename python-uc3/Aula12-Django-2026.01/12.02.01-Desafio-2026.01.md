# Desafio - Model e Templates

## :one: Introdução

**Desafio**: A empresa solicitou que fossem criadas tabelas para utilização e exibição de seus produtos na `template` “produtos”. 

Para completar o desafio os alunos devem realizar a criação da documentação e execução do projeto, envolvendo os seguintes passos

1.  Criação de `model` 
2.  Definição de tipos de cada propriedade 
3.  Uso do comando migrate 
4.  Ativação dos modelos dentro do admin 

Em grupos de no máximo 3 componentes, cada grupo deverá preparar uma documentação básica para apresentar as possíveis tabelas do sistema de forma clara e organizada. 

## :two: Explicação

Imagine que você foi contratado para desenvolver uma aplicação web de **e-commerce** para uma loja chamada **Pé na Estrada**, especializada na venda de calçados esportivos, casuais e sociais. O primeiro passo do projeto é a **modelagem dos dados**, utilizando o `framework` **Django**.

Sua tarefa consiste em criar os modelos necessários para representar as principais entidades do sistema e seus relacionamentos.

### 2.1. Etapas da Atividade

1. Crie um novo projeto Django chamado `config` e um aplicativo interno chamado `produtos`.
   
2. No arquivo `models.py` do aplicativo `produtos`, defina as seguintes classes:
   
   - `Categoria` 🧩
     - Representa os grupos de calçados por tipo de uso. Exemplos: Esportivo, Casual, Social. 
     - Contém nome e descrição opcional, servindo como organizador hierárquico para os produtos.

   - `Produto` 🧩
     - Armazena os calçados disponíveis para venda. 
     - Inclui nome, descrição detalhada, preço com precisão decimal, quantidade em estoque e referência obrigatória à sua categoria.

   - `Cliente` 🧩
      - Perfil estendido do usuário Django (OneToOneField). 
      - Registra dados pessoais como telefone, foto de perfil, sexo (com opções inclusivas), nome social, data de nascimento e CPF único. 
      - Funciona como perfil completo do cliente autenticado.

   - `EnderecoEntrega` 🧩
     - Cadastro de endereços para entrega dos pedidos. 
     - Relaciona-se a um cliente (muitos-para-um) e armazena endereço completo, cidade, estado e CEP. 
     - Um cliente pode ter múltiplos endereços.

   - `Pedido` 🧩
     - Representa uma compra completa do cliente. 
     - Vincula-se ao cliente, endereço de entrega específico e rastreia status (Pendente, Pago, Enviado). 
     - Possui método total_pedido() para calcular valor total dos itens.


   - `ItemPedido` 🧩
     - Detalha cada produto dentro de um pedido específico. 
     - Registra quantidade comprada e preço unitário no momento da compra (evita alterações de preço futuras afetarem pedidos antigos).

   - `ComentarioAvaliação` 🧩
     - Sistema de avaliações e comentários dos clientes sobre produtos. 
     - Relaciona cliente, produto, texto do comentário, nota numérica e data automática de criação.

3. Configure os relacionamentos adequados:
   - Um produto pertence a uma categoria.
   - Um cliente pode ter vários endereços de entrega.
   - Um pedido pertence a um cliente e associa um único endereço de entrega.
   - Um pedido contém vários itens.
   - Cada comentário/avaliação relaciona um cliente a um produto.

   - **Resumindo**:
     - Produto → Categoria (muitos-para-um)
     - Cliente → User (um-para-um)
     - Endereço → Cliente (muitos-para-um)
     - Pedido → Cliente/Endereço (muitos-para-um)
     - ItemPedido → Pedido/Produto (muitos-para-um)
     - Comentário → Produto/Cliente (muitos-para-um)

4. Após definir os modelos, rode as migrações com:
   ```bash
   python manage.py makemigrations
   python manage.py migrate
   ```

5. Crie um superusuário e registre os modelos no `admin.py` para visualizá-los no painel administrativo.

### Desafio Extra

Adicione um método no modelo `Pedido` chamado `total_pedido` que calcula o valor total do pedido somando o valor dos itens (quantidade × preço unitário).  

Exemplo de implementação:

```python
def total_pedido(self):
    total = sum(item.quantidade * item.preco_unitario for item in self.itempedido_set.all())
    return total
```
