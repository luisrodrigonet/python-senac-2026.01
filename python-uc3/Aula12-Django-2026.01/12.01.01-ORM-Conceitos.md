# Aula 12 — Django ORM: Conceitos

O **Django ORM** (*Object-Relational Mapper*) permite trabalhar com o banco de dados usando classes e objetos Python, sem escrever `SQL` manualmente na maior parte do tempo. Cada **modelo** Django normalmente corresponde a uma **tabela**, cada atributo de **campo** corresponde a uma **coluna** e o ORM gera automaticamente a API de consulta. 

Nesta aula, usaremos como base a aplicação de **receitas**, com os modelos `Categoria` e `Receita`.

## 1. O que é o ORM? 🧠 

O `ORM` traduz operações Python em SQL. Em vez de escrever:

```sql
SELECT * FROM receitas_receita WHERE publicada = true;
```

Você escreve:

```python
Receita.objects.filter(publicada=True)
```

Isso traz vantagens importantes:

- **Produtividade:** consultas comuns ficam mais curtas e legíveis.
- **Segurança:** o `ORM` utiliza `querysets` parametrizados, reduzindo riscos de SQL Injection.
- **Portabilidade:** o mesmo código pode funcionar com **SQLite**, **PostgreSQL**, **MySQL** e **MariaDB**, respeitando as particularidades de cada banco.
- **Manutenção:** os modelos concentram a definição dos dados, validações e relacionamentos.

Um modelo Django é uma classe que herda de `django.db.models.Model`; cada campo é um atributo de classe que representa uma coluna no banco.

## 2. Modelo base da aplicação 📦

Vamos partir deste modelo, já adaptado para uma aplicação de receitas:

```python
from django.contrib.auth.models import User
from django.db import models


class Categoria(models.Model):
    """Representa uma categoria de receita, como Sobremesa ou Jantar."""

    nome = models.CharField(max_length=100)

    class Meta:
        verbose_name = "Categoria"
        verbose_name_plural = "Categorias"
        ordering = ["nome"]

    def __str__(self):
        return self.nome


class Receita(models.Model):
    """Representa uma receita publicada no sistema."""

    titulo = models.CharField(max_length=200)

    ingredientes = models.TextField(
        help_text="Informe um ingrediente por linha."
    )

    modo_preparo = models.TextField(
        help_text="Descreva o passo a passo do preparo."
    )

    tempo_preparo = models.PositiveIntegerField(
        help_text="Tempo total de preparo, em minutos."
    )

    data_publicacao = models.DateTimeField(auto_now_add=True)

    publicada = models.BooleanField(default=False)

    # Relação N:N: uma receita pode ter várias categorias
    # e uma categoria pode estar em várias receitas.
    categorias = models.ManyToManyField(
        Categoria,
        related_name="receitas",
        blank=True,
    )

    # Relação 1:N: cada receita pertence a um autor.
    autor = models.ForeignKey(
        User,
        on_delete=models.CASCADE,
        related_name="receitas",
    )

    class Meta:
        verbose_name = "Receita"
        verbose_name_plural = "Receitas"
        ordering = ["-data_publicacao"]

    def __str__(self):
        return self.titulo
```

> **Dica**:
> - O Django cria automaticamente uma chave primária `id` quando nenhum campo é marcado com `primary_key=True`. 
> ---

## 3. Propriedades comuns 🏷️

A maioria dos campos aceita **opções comuns**. Elas controlam **validação**, **comportamento** no banco, formulários e **exibição** no Django Admin.

| Opção | Função | Exemplo |
|---|---|---|
| `null` | Permite `NULL` no banco de dados | `null=True` |
| `blank` | Permite valor vazio em formulários | `blank=True` |
| `default` | Define um valor inicial | `default=False` |
| `choices` | Restringe valores a opções pré-definidas | `choices=Dificuldade.choices` |
| `unique` | Garante valores únicos | `unique=True` |
| `db_index` | Cria índice no banco | `db_index=True` |
| `editable` | Define se aparece em formulários | `editable=False` |
| `help_text` | Texto de ajuda | `help_text="Tempo em minutos"` |
| `verbose_name` | Nome legível do campo | `verbose_name="Título"` |
| `validators` | Adiciona validações | `validators=[MinValueValidator(1)]` |
| `error_messages` | Personaliza mensagens de erro | `error_messages={"required": "..."}` |
| `db_column` | Define o nome da coluna no banco | `db_column="titulo_receita"` |
| `db_comment` | Adiciona comentário à coluna | `db_comment="Título da receita"` |
| `db_default` | Valor padrão calculado pelo banco | `db_default=Now()` |
| `primary_key` | Define a chave primária | `primary_key=True` |


> **Dica**: 
> 
> `null` e `blank` são diferentes: 
> - `null=True` afeta o **banco de dados**,  
> - `blank=True` afeta a **validação de formulários**. 
> 
> Para campos de texto, a prática recomendada é usar `blank=True` com `default=""`, evitando dois “estados vazios” diferentes: `NULL` e string vazia. 

### 3.1. Exemplo aplicado às receitas

```python
from django.core.validators import MinValueValidator
from django.db import models


class Receita(models.Model):
    """Representa uma receita publicada no sistema."""

    titulo = models.CharField(
        max_length=200,
        verbose_name="Título",
        help_text="Nome da receita.",
    )

    ingredientes = models.TextField(
        verbose_name="Ingredientes",
        help_text="Informe um ingrediente por linha.",
    )

    modo_preparo = models.TextField(
        verbose_name="Modo de preparo",
        help_text="Descreva o passo a passo do preparo.",
    )

    tempo_preparo = models.PositiveIntegerField(
        verbose_name="Tempo de preparo",
        help_text="Tempo total de preparo, em minutos.",
        validators=[MinValueValidator(1)],
    )

    publicada = models.BooleanField(
        verbose_name="Publicada",
        default=False,
        help_text="Define se a receita está visível no site.",
    )
```

## 4. Campos numéricos 🔢

### 4.1. `IntegerField`

Armazena números inteiros. É adequado para quantidades, anos, contagens e identificadores numéricos simples.

```python
porcoes = models.IntegerField(default=1)
```

### 4.2. `PositiveIntegerField`

Aceita apenas valores não negativos, incluindo o zero. É o campo ideal para `tempo_preparo`, pois minutos não podem ser negativos.

```python
tempo_preparo = models.PositiveIntegerField(
    help_text="Tempo total de preparo, em minutos.",
    validators=[MinValueValidator(1)],
)
```

Aqui, `PositiveIntegerField` impede valores negativos e `MinValueValidator(1)` exige pelo menos 1 minuto.

### 4.3. `DecimalField`

Use `DecimalField` para valores que exigem precisão, especialmente dinheiro. Ele exige `max_digits` e `decimal_places`.

```python
custo_estimado = models.DecimalField(
    max_digits=8,       # Total de dígitos, incluindo as casas decimais
    decimal_places=2,   # Casas decimais
    max_digits=8,
    decimal_places=2,
    help_text="Custo estimado da receita em reais.",
)
```

Por exemplo, `max_digits=8` e `decimal_places=2` permitem valores até `999999.99`.

### 4.4. `FloatField`

`FloatField` armazena números decimais aproximados. Não é a melhor escolha para dinheiro, pois operações de ponto flutuante podem gerar imprecisões.

```python
porcao_em_gramas = models.FloatField(
    help_text="Peso aproximado de uma porção, em gramas.",
)
```

## 5. Campos de texto ✍️

### 5.1. `CharField`

Use `CharField` para textos curtos ou de tamanho limitado, como título, nome e descrição resumida. O parâmetro `max_length` é obrigatório.

```python
titulo = models.CharField(max_length=200)
```

### 5.2. `TextField`

Use `TextField` para textos longos, como ingredientes e modo de preparo. Ele não exige `max_length` no banco, embora seja possível usar `max_length` para validar formulários.

```python
ingredientes = models.TextField(
    help_text="Informe um ingrediente por linha."
)

modo_preparo = models.TextField(
    help_text="Descreva o passo a passo do preparo."
)
```

### 5.3. `SlugField`

`SlugField` é ideal para URLs amigáveis. Um slug converte, por exemplo, “Bolo de Cenoura” em `bolo-de-cenoura`.

```python
from django.utils.text import slugify


class Receita(models.Model):
    titulo = models.CharField(max_length=200)
    slug = models.SlugField(
        max_length=250,
        unique=True,
        blank=True,
    )

    def save(self, *args, **kwargs):
        # Gera o slug automaticamente a partir do título,
        # caso ele ainda não tenha sido definido.
        if not self.slug:
            self.slug = slugify(self.titulo)

        super().save(*args, **kwargs)
```

Com esse campo, uma URL pode ficar assim:

```text
/receitas/bolo-de-cenoura/
```

Em vez de:

```text
/receitas/17/
```

## 6. Campos de data e hora 📅

### 6.1. `DateField`

Armazena apenas uma data, como `2026-11-09`.

```python
data_atualizacao = models.DateField(auto_now=True)
```

### 6.2. `DateTimeField`

Armazena data e hora. É o campo usado em `data_publicacao`.

```python
data_publicacao = models.DateTimeField(auto_now_add=True)
```

### 6.3. `TimeField`

Armazena apenas horário, como `18:30:00`.

```python
horario_ideal = models.TimeField(
    null=True,
    blank=True,
    help_text="Horário recomendado para servir a receita.",
)
```

### 6.4. `DurationField`

Armazena durações, como “2 horas e 30 minutos”.

```python
from datetime import timedelta

tempo_descanso = models.DurationField(
    default=timedelta(minutes=30),
    help_text="Tempo de descanso da massa.",
)
```

### 6.5. `auto_now` e `auto_now_add`

| Opção | Quando é definida | Uso comum |
|---|---|---|
| `auto_now_add=True` | Apenas na criação do objeto | Data de publicação |
| `auto_now=True` | Em cada chamada de `save()` | Data da última atualização |

```python
data_publicacao = models.DateTimeField(auto_now_add=True)
data_atualizacao = models.DateTimeField(auto_now=True)
```

> ⚠️ Atenção:
> --- 
> - Não use `default`, `auto_now` e `auto_now_add` juntos no mesmo campo. Eles são mutuamente exclusivos.
> --- 

## 7. Campos booleanos ✅

`BooleanField` armazena apenas `True` ou `False`.

```python
publicada = models.BooleanField(
    default=False,
    help_text="Define se a receita está visível no site.",
)
```

Para permitir três estados — verdadeiro, falso ou indefinido — use `null=True`:

```python
aprovada = models.BooleanField(
    default=None,
    null=True,
    help_text="Indica se a receita foi revisada pela moderação.",
)
```

## 🖼️ Campos de arquivo

### `FileField`

Use `FileField` para arquivos genéricos, como PDFs de fichas técnicas.

```python
arquivo_pdf = models.FileField(
    upload_to="receitas/pdfs/%Y/%m/",
    blank=True,
    null=True,
)
```

### `ImageField`

Use `ImageField` para imagens. Ele valida que o arquivo enviado é uma imagem e exige a biblioteca **Pillow**.

```python
foto = models.ImageField(
    upload_to="receitas/fotos/%Y/%m/",
    blank=True,
    null=True,
)
```

Para usar uploads, configure no `settings.py`:

```python
import os
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent.parent

MEDIA_URL = "/media/"
MEDIA_ROOT = os.path.join(BASE_DIR, "media")
```

E, no `urls.py` do projeto, durante o desenvolvimento:

```python
from django.conf import settings
from django.conf.urls.static import static
from django.contrib import admin
from django.urls import path

urlpatterns = [
    path("admin/", admin.site.urls),
]

if settings.DEBUG:
    urlpatterns += static(
        settings.MEDIA_URL,
        document_root=settings.MEDIA_ROOT,
    )
```

## 🔗 Relacionamentos

### `ForeignKey` — muitos para um

Uma `ForeignKey` representa uma relação **muitos-para-um**. No nosso caso, várias receitas podem pertencer ao mesmo autor.

```python
autor = models.ForeignKey(
    User,
    on_delete=models.CASCADE,
    related_name="receitas",
)
```

- `User` é o modelo relacionado.
- `on_delete` define o que acontece quando o autor é excluído.
- `related_name="receitas"` permite acessar as receitas de um usuário por `usuario.receitas.all()`.

O Django cria automaticamente uma coluna `autor_id` no banco para armazenar a relação. 

### Opções de `on_delete`

| Opção | Comportamento |
|---|---|
| `CASCADE` | Exclui os objetos relacionados |
| `PROTECT` | Impede a exclusão se houver objetos relacionados |
| `RESTRICT` | Impede a exclusão, com restrição mais rigorosa |
| `SET_NULL` | Define o campo como `NULL`; exige `null=True` |
| `SET_DEFAULT` | Define o valor padrão; exige `default` |
| `SET(valor_ou_funcao)` | Define um valor específico |
| `DO_NOTHING` | Não faz nada; pode causar erro de integridade |

Para receitas, `CASCADE` é adequado se, ao excluir um usuário, você deseja remover também as receitas dele. Se quiser preservar o conteúdo, considere `SET_NULL` com `null=True`.

```python
autor = models.ForeignKey(
    User,
    on_delete=models.SET_NULL,
    null=True,
    related_name="receitas",
)
```

### `related_name`

Sem `related_name`, o Django cria o acesso reverso padrão:

```python
usuario.receita_set.all()
```

Com `related_name="receitas"`, o acesso fica mais claro:

```python
usuario.receitas.all()
```

```python
usuario = User.objects.get(username="luis")
receitas_do_usuario = usuario.receitas.all()
```

### `ManyToManyField` — muitos para muitos

Uma receita pode pertencer a várias categorias, e uma categoria pode conter várias receitas. Esse é um relacionamento **muitos-para-muitos**.

```python
categorias = models.ManyToManyField(
    Categoria,
    related_name="receitas",
    blank=True,
)
```

O Django cria automaticamente uma tabela intermediária para armazenar os pares `receita_id` e `categoria_id`. 

```python
receita = Receita.objects.get(titulo="Bolo de cenoura")

# Adiciona categorias
receita.categorias.add(
    Categoria.objects.get(nome="Sobremesa"),
    Categoria.objects.get(nome="Bolos"),
)

# Lista as categorias da receita
receita.categorias.all()

# Lista as receitas de uma categoria
categoria = Categoria.objects.get(nome="Sobremesa")
categoria.receitas.all()
```

### Modelo intermediário

Use `through` quando precisar guardar informações sobre a relação, como a ordem das categorias ou uma observação.

```python
class ReceitaCategoria(models.Model):
    """Armazena informações adicionais sobre a relação entre receita e categoria."""

    receita = models.ForeignKey(
        Receita,
        on_delete=models.CASCADE,
        related_name="categoria_receitas",
    )

    categoria = models.ForeignKey(
        Categoria,
        on_delete=models.CASCADE,
        related_name="receita_categorias",
    )

    destaque = models.BooleanField(
        default=False,
        help_text="Indica se a categoria é a principal da receita.",
    )

    class Meta:
        unique_together = ["receita", "categoria"]

    def __str__(self):
        return f"{self.receita} - {self.categoria}"


class Receita(models.Model):
    # ...

    categorias = models.ManyToManyField(
        Categoria,
        through="ReceitaCategoria",
        related_name="receitas",
        blank=True,
    )
```

Com `through`, crie a relação pelo modelo intermediário:

```python
ReceitaCategoria.objects.create(
    receita=receita,
    categoria=categoria,
    destaque=True,
)
```

## 🎛️ `choices`

Use `choices` para limitar o campo a opções pré-definidas. A forma moderna e recomendada é usar `TextChoices` ou `IntegerChoices`.

```python
from django.db import models


class Dificuldade(models.TextChoices):
    FACIL = "FACIL", "Fácil"
    MEDIO = "MEDIO", "Médio"
    DIFICIL = "DIFICIL", "Difícil"


class Receita(models.Model):
    # ...

    dificuldade = models.CharField(
        max_length=10,
        choices=Dificuldade.choices,
        default=Dificuldade.FACIL,
        verbose_name="Dificuldade",
    )
```

Uso:

```python
receita = Receita.objects.create(
    titulo="Bolo de cenoura",
    ingredientes="Cenoura\nFarinha\nOvos",
    modo_preparo="Misture e asse.",
    tempo_preparo=45,
    dificuldade=Dificuldade.FACIL,
)

receita.get_dificuldade_display()
# 'Fácil'
```

## 🧪 Validações

Validadores garantem que os dados sigam regras de negócio antes de serem salvos.

```python
from django.core.validators import MinValueValidator, MaxValueValidator
from django.db import models


class Receita(models.Model):
    # ...

    tempo_preparo = models.PositiveIntegerField(
        validators=[
            MinValueValidator(1, message="O tempo mínimo é 1 minuto."),
            MaxValueValidator(1440, message="O tempo máximo é 24 horas."),
        ],
    )
```

Também é possível criar validadores personalizados:

```python
from django.core.exceptions import ValidationError


def validar_tempo_preparo(value):
    """Garante que o tempo de preparo seja positivo."""

    if value <= 0:
        raise ValidationError("O tempo de preparo deve ser maior que zero.")
```

## 🗃️ `Meta` e `__str__`

A classe interna `Meta` configura o comportamento do modelo.

```python
class Meta:
    verbose_name = "Receita"
    verbose_name_plural = "Receitas"
    ordering = ["-data_publicacao"]
```

- `verbose_name`: nome singular exibido no Django Admin.
- `verbose_name_plural`: nome plural exibido no Django Admin.
- `ordering`: ordenação padrão das consultas.

O método `__str__` define como o objeto aparece em textos, logs e no Django Admin.

```python
def __str__(self):
    return self.titulo
```

## 🚀 Consultas iniciais

```python
from receitas.models import Categoria, Receita

# Cria uma categoria
sobremesa = Categoria.objects.create(nome="Sobremesa")

# Cria uma receita
receita = Receita.objects.create(
    titulo="Bolo de cenoura",
    ingredientes="Cenoura\nFarinha\nOvos\nAçúcar",
    modo_preparo="Misture os ingredientes e asse por 40 minutos.",
    tempo_preparo=45,
    autor=usuario,
)

# Relaciona a receita à categoria
receita.categorias.add(sobremesa)

# Consultas
Receita.objects.filter(publicada=True)
Receita.objects.filter(tempo_preparo__lte=30)
Receita.objects.filter(categorias__nome="Sobremesa")
Categoria.objects.filter(receitas__publicada=True)
```

O Django ORM transforma essas consultas em SQL de forma segura e consistente, permitindo filtrar, ordenar, agregar e navegar entre modelos relacionados. 

## ✅ Boas práticas

- Use `CharField` para textos curtos e `TextField` para textos longos.
- Use `DecimalField` para dinheiro e `FloatField` apenas para medidas aproximadas.
- Prefira `blank=True` e `default=""` em campos de texto opcionais.
- Sempre defina `on_delete` em `ForeignKey` e `OneToOneField`.
- Use `related_name` descritivo para melhorar a legibilidade do código.
- Use `choices` para valores fixos, como dificuldade ou status.
- Use `validators` para regras de negócio, como tempo mínimo de preparo.
- Use `__str__` para representar objetos de forma legível.
- Use `Meta.ordering` apenas quando a ordenação padrão fizer sentido para o modelo.
