# Python & Django: Revisão de Laços de Repetição na Web

> **Objetivo:** Compreender a lógica de laços (`for` e `while`) no backend Python e entender como exibir coleções de dados dinamicamente no navegador com o Django.
> 
> Em um ambiente web com Django, o fluxo de entrada e saída muda: em vez de `input()` e `print()` no terminal, a lógica é processada nas **views** (utilizando requisições HTTP e formulários) e os dados são exibidos na tela via **templates HTML**.
> 
> Nesta aula criaremos **3 exemplos práticos** utilizando o laço `while` dentro da lógica de uma aplicação Django.
>
> Cada exemplo mostra como o `while` resolve problemas comuns de processamento na camada de visão (`views.py`) ou em scripts internos, passando os resultados para serem exibidos dinamicamente nos templates.

### Exemplo 1: Simulação de Amortização de Dívida / Empréstimo

Neste exemplo, o laço `while` calcula a evolução de uma dívida mês a mês até que o saldo devedor seja zerado (`while saldo > 0`).

#### `views.py`

```python
from django.shortcuts import render

def amortizacao_divida(request):
    tabela = []
    saldo = 0
    
        saldo = float(request.POST.get('valor_total', 0))
        parcela_mensal = float(request.POST.get('parcela', 0))
        mes = 1

        # O laço while continua até a dívida ser quitada
        while saldo > 0:
            if saldo < parcela_mensal:
                pago = saldo
                saldo = 0
            else:
                pago = parcela_mensal
                saldo -= parcela_mensal

            tabela.append({
                'mes': mes,
                'pago': round(pago, 2),
                'saldo_restante': round(saldo, 2)
            })
            mes += 1

    return render(request, 'loops_app/amortizacao.html', {'tabela': tabela})

```

No Django, as *views* são funções (ou classes) Python que recebem um objeto `HttpRequest` e devolvem uma resposta HTTP (`HttpResponse`), geralmente renderizando um template HTML com dados dinâmicos. Neste arquivo fica concentrada toda a lógica de repetição do `while`:

* **Função `amortizacao_divida(request)`:**
* **Verificação do método (`request.method == "POST"`):** Garante que os cálculos só ocorram quando o usuário envia os dados pelo formulário.


* **Captura de parâmetros:** Obtém o `valor_total` e a `parcela` enviados pelo usuário.
* **O laço `while saldo > 0`:** Executa mês a mês subtraindo o valor da parcela. Caso o saldo seja menor que a parcela, ele ajusta para quitar exatamente o que resta e zera o saldo, evitando pagamentos a mais.
* **Dicionário de contexto e `render()`:** Armazena a lista de meses calculados e passa para o template `amortizacao.html` desenhar a tabela.





#### `templates/loops_app/amortizacao.html`

```html
<!DOCTYPE html>
<html lang="pt-br">
<head>
    <meta charset="UTF-8">
    <title>Simulação de Amortização</title>
</head>
<body>
    <h2>Simulador de Quitação de Dívida (Laço While)</h2>
    <form method="post">
        {% csrf_token %}
        <label>Valor Total (R$):</label>
        <input type="number" name="valor_total" step="0.01" required>
        
        <label>Pagamento Mensal (R$):</label>
        <input type="number" name="parcela" step="0.01" required>
        
        <button type="submit">Calcular</button>
    </form>

    {% if tabela %}
        <h3>Cronograma de Pagamento:</h3>
        <table border="1">
            <tr>
                <th>Mês</th>
                <th>Valor Pago</th>
                <th>Saldo Restante</th>
            </tr>
            {% for linha in tabela %}
            <tr>
                <td>{{ linha.mes }}</td>
                <td>R$ {{ linha.pago }}</td>
                <td>R$ {{ linha.saldo_restante }}</td>
            </tr>
            {% endfor %}
        </table>
    {% endif %}
</body>
</html>

```

Os templates são arquivos HTML que representam a camada de apresentação visual. Eles usam a linguagem de templates do Django (DTL) para exibir os dados preparados pelas *views*:

* **`amortizacao.html`:**
* **Tag `{% csrf_token %}`:** Elemento de segurança obrigatório em formulários `POST` no Django para proteger contra ataques do tipo *Cross-Site Request Forgery*.
* **Tag `{% if tabela %}`:** Exibe a tabela de pagamentos apenas se houver dados calculados.


* **Tag `{% for linha in tabela %} ... {% endfor %}`:** Demonstra a integração entre os laços — enquanto o backend utilizou `while` para calcular as parcelas, o template usa um `for` para percorrer e imprimir cada linha na tabela HTML.

### Exemplo 2: Fatoração Numérica e Decomposição em Primos

Aqui, o `while` é utilizado para decompor um número inteiro em fatores primos, demonstrando divisões sucessivas e controle de fluxo com contadores.

#### `views.py`

```python
from django.shortcuts import render

def fatores_primos(request):
    fatores = []
    numero_original = None

    if request.method == "POST":
        numero = int(request.POST.get('numero', 1))
        numero_original = numero
        divisor = 2

        # Reduz o número dividindo pelos fatores primos possíveis
        while numero > 1:
            if numero % divisor == 0:
                fatores.append(divisor)
                numero //= divisor
            else:
                divisor += 1

    contexto = {
        'numero': numero_original,
        'fatores': fatores
    }
    return render(request, 'loops_app/fatores.html', contexto)

```

* **Função `fatores_primos(request)`:**
* **O laço `while numero > 1`:** Reduz o número recebido testando sucessivas divisões pelo menor divisor possível (iniciado em `2`).
* **Condição interna:** Se o resto da divisão (`numero % divisor == 0`) for zero, adiciona o divisor na lista de fatores e reduz o número via divisão inteira (`numero //= divisor`); caso contrário, incrementa o divisor (`divisor += 1`).


#### `templates/loops_app/fatores.html`

```html
<!DOCTYPE html>
<html lang="pt-br">
<head>
    <meta charset="UTF-8">
    <title>Fatores Primos</title>
</head>
<body>
    <h2>Decomposição em Fatores Primos</h2>
    <form method="post">
        {% csrf_token %}
        <label>Digite um número inteiro:</label>
        <input type="number" name="numero" min="2" required>
        <button type="submit">Decompor</button>
    </form>

    {% if fatores %}
        <p>Os fatores primos de <strong>{{ numero }}</strong> são:</p>
        <ul>
            {% for fator in fatores %}
                <li>{{ fator }}</li>
            {% endfor %}
        </ul>
    {% endif %}
</body>
</html>

```

* **`fatores.html`:**
* Contém o formulário com entrada numérica (`min="2"`).
* Exibe dinamicamente a lista de fatores primos encontrados via `{% for fator in fatores %}`.

### Exemplo 3: Geração de Protocolo Único com Validação no Banco (ORM)

Um caso muito frequente em backend Django: gerar um código aleatório (ou protocolo) e usar o laço `while` para garantir que o código gerado **não exista** previamente no banco de dados.

#### `views.py`

```python
import random
import string
from django.shortcuts import render
from django.contrib.auth.models import User  # Exemplo usando modelo User

def gerar_protocolo_atendimento(request):
    protocolo = None

    if request.method == "POST":
        existe = True

        # O laço roda até encontrar um código que não esteja cadastrado
        while existe:
            # Gera um código alfanumérico aleatório de 6 caracteres
            codigo_candidato = ''.join(random.choices(string.ascii_uppercase + string.digits, k=6))
            
            # Verifica se o código já é usado como username no banco
            # (poderia ser qualquer model com campo unique=True)
            if not User.objects.filter(username=codigo_candidato).exists():
                protocolo = codigo_candidato
                existe = False  # Sai do laço ao encontrar um código livre

    return render(request, 'loops_app/protocolo.html', {'protocolo': protocolo})

```

* **Função `gerar_protocolo_atendimento(request)`:**
* **O laço `while existe`:** Continua gerando combinações aleatórias de 6 dígitos até encontrar uma que **não** exista no banco de dados.
* **Consulta ao ORM (`User.objects.filter(...).exists()`):** Garante unicidade no banco de dados antes de concluir a requisição e sair do laço (`existe = False`).


#### `templates/loops_app/protocolo.html`

```html
<!DOCTYPE html>
<html lang="pt-br">
<head>
    <meta charset="UTF-8">
    <title>Gerador de Protocolo</title>
</head>
<body>
    <h2>Gerar Novo Protocolo Único</h2>
    <form method="post">
        {% csrf_token %}
        <button type="submit">Gerar Novo Protocolo</button>
    </form>

    {% if protocolo %}
        <p>Seu protocolo de atendimento é: <strong>{{ protocolo }}</strong></p>
    {% endif %}
</body>
</html>

```

* **`protocolo.html`:**
* Fornece um botão de ação para disparar a geração do código.
* Utiliza `{% if protocolo %}` para mostrar o protocolo gerado na tela após o processamento da requisição.

### Registro das Rotas (`urls.py`)



Para testar todos os exemplos, adicione as rotas ao arquivo `urls.py` do aplicativo:

```python
from django.urls import path
from . import views

urlpatterns = [
    path('amortizacao/', views.amortizacao_divida, name='amortizacao'),
    path('fatores/', views.fatores_primos, name='fatores'),
    path('protocolo/', views.gerar_protocolo_atendimento, name='protocolo'),
]

```

O arquivo `urls.py` define a tabela de roteamento (URLconf), mapeando padrões de endereços digitados no navegador para as respectivas funções no arquivo `views.py`:

**Função `path(rota, view, name)`:**

* **Primeiro argumento (ex: `'amortizacao/'`):** O caminho da URL acessada pelo cliente HTTP.
* **Segundo argumento (ex: `views.amortizacao_divida`):** A função em Python que o Django executa quando essa URL é chamada.
* **Terceiro argumento (`name='...'`):** Um identificador único que permite referenciar a rota de forma reversa sem fixar a URL manualmente no código.
